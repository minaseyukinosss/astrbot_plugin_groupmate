# Groupmate 消息处理链控制台设计

日期：2026-08-21  
状态：待用户审阅

## 1. 目标

把当前按投影类型堆叠的“事件流”改成以一条 QQ 群消息为中心的可解释处理链。管理员打开运行中心后，应能立即回答：

1. Groupmate 当前是否在工作；
2. 一条消息由 Groupmate 还是 AstrBot 其他插件处理；
3. Groupmate 如何理解消息、为何回复或沉默；
4. SHADOW 是否只生成候选回复，正式模式是否真的通过 NapCat 发到 QQ；
5. 哪位群成员触发了这次处理。

页面不展示模型思维链、系统提示词或原始敏感载荷，只展示经过裁剪的事实、可解释摘要、原因码、阶段状态和发送回执。

## 2. 系统边界

生产数据流为：

```text
QQ群
  → NapCat
  → OneBot v11 反向 WebSocket
  → AstrBot aiocqhttp 适配器
  → AstrMessageEvent
  → AstrBot 指令及其他插件
  → Groupmate 后置闲聊处理器（priority=-100）
  → Social Runtime 注意 / 场景理解 / 参与判断
  → SHADOW 候选记录或 SOCIAL_RUNTIME 回复计划
  → AstrBot OneBot 客户端
  → NapCat
  → QQ
```

Groupmate 继续遵循“外部指令和专用插件优先”的边界。控制台可以观察消息是否进入 Groupmate，但不能把其他插件的业务逻辑吸收到 Social Runtime 核心，也不能声称知道 AstrBot 未提供的具体插件处理结果。

## 3. 现状问题

当前运行中心分别读取 `activity`、`scenes`、`evaluation`、`tasks` 投影，再由浏览器按时间排序。其问题是：

- 同一条消息产生的多个阶段没有作为同一条链展示；
- `correlation_id` 在平台消息入口已经建立，但控制面投影没有保留；
- 历史 SHADOW 判断会被误认为当前运行状态；
- `OFF` 只结合 `paused` 判断，导致“未启用”和“运行中”同时出现；
- `AMBIENT`、`forced_observe`、effect ID 等内部术语直接暴露；
- Groupmate 的后置监听在其他插件 `stop_event()` 后不会运行，因此现有链路对“外部接管”完全不可见；
- 浏览器运行时拼出的图标相对路径不会被 AstrBot Plugin Pages 重写，出现破图。

## 4. 方案选择

### 4.1 不采用：前端按时间猜测关联

继续合并现有投影、用时间窗口把记录拼成一条消息，改动较小，但并发群消息、延迟认知任务和回复引用都会导致误关联，不能作为可信控制台。

### 4.2 不采用：只为现有投影补 `correlation_id`

该方案能正确关联进入 Groupmate 的消息，但仍看不到在 AstrBot 前置插件处终止传播的消息，无法解释视频链接、表情指令为何没有进入闲聊链路。

### 4.3 采用：双观察点与后端消息链投影

增加一个只记录平台事实的前置观察点，保留现有后置 Groupmate 处理点。后端以 QQ `message_id` 对应的平台事件 ID 为链路根，聚合各阶段并输出专用 `traces` 只读投影。

该方案让前端消费稳定的业务读模型，不再推测事件关系；同时不改变现有消息归属、认知和发送决策。

## 5. 消息入口设计

### 5.1 前置观察点

在插件组合根增加高优先级群消息监听器，只执行以下操作：

- 调用现有 `AstrBotEventTranslator` 生成稳定的平台事件身份；
- 写入一条幂等的消息入口记录；
- 保存群、发送者、时间、裁剪后的消息摘要、媒体类型和外部触发提示；
- 不调用模型、不修改 AstrBot 事件、不发送消息、不停止传播。

监听范围仅限 `enabled_groups`。它不是 AstrBot 全局审计器。

### 5.2 后置处理点

现有 `priority=-100` 监听器保持为唯一 Social Runtime 入口。开始执行时，把对应消息链标记为“已进入 Groupmate”，再按现有流程完成 ingest、drain、SHADOW 或正式回复。

### 5.3 未进入 Groupmate

前置记录存在、但后置处理点没有留下“已进入”阶段时，读模型显示：

- 若消息命中已配置的外部指令前缀或链接域名：`交给外部能力`；
- 否则：`未进入 Groupmate`，说明为“消息传播在 Groupmate 之前结束”。

页面不得猜测具体插件名称或宣称插件执行成功。只有配置中明确给出显示标签时，才可显示“视频解析”等能力名称。

## 6. 消息链读模型

新增 `traces` 控制面投影。每个条目表示一条平台消息，核心结构为：

```json
{
  "trace_id": "trace:<opaque-id>",
  "source_message_id": "<redacted-or-opaque>",
  "occurred_at": 1787300000,
  "actor": {
    "member_ref": "member:<opaque-id>",
    "display_name": "阿杰",
    "avatar_ref": "participant:<opaque-id>"
  },
  "message": {
    "summary": "今晚能上线吗？",
    "media_types": []
  },
  "route": {
    "owner": "GROUPMATE",
    "label": "Groupmate 闲聊",
    "reason": "普通群聊消息"
  },
  "understanding": {
    "summary": "正在询问产品上线进度",
    "status": "COMPLETED"
  },
  "decision": {
    "outcome": "RESPOND",
    "label": "准备回复",
    "reasons": ["直接询问", "当前话题相关"]
  },
  "delivery": {
    "mode": "SHADOW",
    "status": "OBSERVED",
    "label": "已判断，未向 QQ 发送"
  },
  "timing": {
    "total_ms": 1380
  },
  "stages": []
}
```

`trace_id`、`member_ref` 和 `avatar_ref` 均为控制面不透明引用。浏览器不需要直接读取数据库主键或拼接外部地址。

### 6.1 阶段词汇

详情面板使用固定阶段：

1. `RECEIVED`：NapCat/AstrBot 已上报群消息；
2. `ROUTED`：确定 Groupmate、外部能力或未进入；
3. `ATTENDED`：Groupmate 建立注意帧；
4. `UNDERSTOOD`：完成场景理解；
5. `DECIDED`：完成回复、沉默或动作判断；
6. `PLANNED`：已生成候选回复或动作；
7. `DELIVERED`：正式模式获得发送回执。

缺少的阶段不伪造。SHADOW 在 `PLANNED` 后明确结束为“仅观察”；沉默在 `DECIDED` 后明确结束为“保持沉默”；外部路由在 `ROUTED` 后结束为“Groupmate 未接管”。

### 6.2 关联规则

- 平台入口以 `event_id = qq:<message_id>` 为根；
- `correlation_id` 和 `causation_id` 在 Journal 到投影的过程中保留为内部关联字段；
- 回复计划、outbox part 和发送回执通过现有 correlation/plan/part 关系回溯到根消息；
- 控制面只返回不透明 trace 引用，不公开原始关联图；
- 无法唯一关联的记录进入“技术记录”，不强行合并到消息链。

## 7. 参与者资料

### 7.1 核心边界

Social Runtime 核心继续只依赖成员身份和事件中的可观察名称。头像解析、缓存和页面 URL 属于控制面展示适配层，封装为 `ParticipantDirectory`，不进入认知、关系或决策模型。

### 7.2 昵称优先级

```text
群名片 card
→ QQ 昵称 nickname
→ ParticipantDirectory 中最近一次有效名称
→ “群成员”
```

新消息到达时更新展示名称。历史链路保留当时的安全快照，避免成员改名后改变审计语义。

### 7.3 头像策略

- OneBot 群消息不携带稳定头像内容；
- 使用 QQ 号在服务端解析头像来源，并缓存于插件数据目录；
- 页面通过 Groupmate 自己的只读头像 API 获取，不直接访问外部 QQ 头像域名；
- 成功缓存 24 小时，失败缓存较短时间以避免重复请求；
- 获取失败、无 QQ 号或非 QQ 平台时，返回基于 `member_ref` 稳定生成的首字母/色块头像；
- 不为消息中的所有 @、引用成员做批量抓取，只展示已有缓存；
- 头像缓存不写入 Social Runtime 事件数据库。

## 8. 控制面 API

新增只读端点：

- `GET traces`：返回当前群的消息链摘要，支持状态、路由和时间筛选；
- `GET traces/<trace_id>`：返回一条链的阶段、证据摘要和候选输出；
- `GET participants/<avatar_ref>/avatar`：返回缓存头像或本地生成的降级头像。

现有 SSE 投影流增加 `traces` 更新事件。页面仍通过 `window.AstrBotPluginPage` bridge 访问，不直接读取 AstrBot Cookie 或 NapCat API。

## 9. 运行中心界面

### 9.1 首屏状态

首屏先展示唯一、无矛盾的运行状态：

- `OFF`：Groupmate 当前未运行，并提示检查启用群和文本模型；隐藏暂停按钮及当前判断指标；
- `SHADOW`：正在观察，不会向群内发消息；
- `SOCIAL_RUNTIME`：正在运行，符合治理条件的回复会发送到群内；
- 已暂停：覆盖运行模式显示为暂停，并提供恢复操作。

历史记录单独标注为历史，不参与当前状态文案。

### 9.2 默认事件流

默认主表每条群消息只占一行：

| 时间 | 参与者与消息 | 处理路径 | Groupmate 的理解 | 决定 | 最终结果 |
|---|---|---|---|---|---|

参与者单元显示 28–32px 头像、群名片和消息摘要。状态使用稳定语义色：Groupmate、外部能力、沉默、SHADOW、已发送、失败。

默认筛选为“全部消息”，次级筛选为“已回复”“保持沉默”“外部接管”“处理失败”。原始多投影事件流移动到“技术记录”页签。

### 9.3 详情面板

点击消息行后，右侧详情依次展示：

1. 发送者头像、群名片、时间和安全消息摘要；
2. 收到 → 路由 → 注意 → 理解 → 判断 → 计划 → 发送的阶段时间线；
3. 候选回复或实际回复；
4. 公开原因码和治理限制；
5. 可折叠技术信息。

`AMBIENT` 显示为“观察群聊上下文”，`forced_observe` 显示为“SHADOW 模式禁止发送”。内部值只在技术信息中保留。

### 9.4 响应式与资源

- 桌面宽度保留侧栏文字，不在 1280 CSS 像素附近提前折叠；
- 表格在较窄宽度改为消息链卡片，不横向压缩关键文案；
- 动态图标改为内联 SVG symbol 或由 HTML/CSS 声明的资源，确保 AstrBot 能重写资源路径；
- 继续适配 AstrBot 注入的 `data-theme=light|dark`。

### 9.5 样式修复基线

本次不是只替换事件表内容，必须同步修复实际 AstrBot iframe 中已经出现的显示问题：

- 清除所有破图占位符，图标失败时也不得撑开布局或显示浏览器损坏图标；
- 将侧栏文字折叠断点从普通桌面宽度下移，仅在真正无法容纳时切换为紧凑导航；
- 顶部群组、Persona 和运行摘要卡允许内容收缩，群号、状态和版本不得互相覆盖；
- 表头、单元格、状态标签和操作按钮设置明确的最小/最大宽度，长消息摘要使用两行截断并可在详情中查看完整安全摘要；
- 详情面板在空间不足时作为覆盖层打开，不挤压主表到不可读宽度；
- 浅色主题正文、次级文字、边框和状态色满足可读对比度；深色主题沿用同一语义层级；
- 控件采用一致高度、圆角、焦点态和禁用态，不混用浏览器默认样式；
- iframe 视口采用 CSS 像素断点验证，不能按截图物理像素误判桌面宽度；
- 加载、空数据、断线和错误状态必须占用稳定空间，避免内容跳动或互相覆盖。

桌面优先验证约 1272 CSS 像素宽度，这是已安装页面发生侧栏折叠和内容拥挤的实际条件；同时补充一个窄屏结构检查和浅色/深色主题检查。

## 10. 错误与降级

- 前置入口写入失败不得阻断 AstrBot 消息传播；记录健康告警；
- 消息已进入 Groupmate 但后续阶段缺失时，显示“处理未完成”，不自动归为沉默；
- 头像加载失败只影响头像，不影响事件行和昵称；
- NapCat 发送没有 `message_id` 时显示“发送结果未知”，不显示成功；
- 投影消费失败时保留最后成功数据，并显示同步降级；
- 页面断线时显示“数据暂未更新”，不把连接状态解释为 Groupmate 已停止。

## 11. 数据保留与隐私

- 使用现有安全裁剪、链接替换和敏感数字遮罩规则；
- 头像 API 只允许读取已登记的不透明 `avatar_ref`，禁止任意 QQ 号或路径输入；
- 页面不展示系统提示、模型思维链、鉴权信息或原始 Journal JSON；
- 消息链沿用控制面现有管理员权限；
- 头像缓存可删除且不影响核心数据恢复。

## 12. 实施范围

预计修改：

- `main.py`：增加轻量前置观察处理器；
- `groupmate/adapters/`：入口记录、参与者目录和头像适配；
- `groupmate/social_runtime/control/`：新增 traces 投影、查询与流更新；
- `groupmate/adapters/web_api.py`：注册消息链和头像只读 API；
- `pages/settings/`：重做运行中心消息链表格、状态卡和详情面板；
- `pages/settings/styles/`：修复资源、断点、截断、对比度和详情面板布局；
- `tests/`：增加少量消息关联、外部终止、昵称/头像降级和 OFF/SHADOW 展示测试。

不在本次范围内：

- 读取或展示其他插件的内部日志；
- 自动识别未配置插件的真实名称；
- 修改 AstrBot 的插件分发器；
- 把视频解析、表情生成等能力迁入 Groupmate；
- 建立通用的 AstrBot 全局 APM 系统。

## 13. 验收标准

1. 一条 QQ 群消息在默认事件流中只显示一行；
2. 点击后能看到实际存在的处理阶段且顺序正确；
3. 外部触发消息不会进入 Groupmate 闲聊判断，并能解释为外部能力或未进入；
4. SHADOW 明确显示“已判断，未向 QQ 发送”；
5. 正式发送只有拿到 OneBot/NapCat 回执后才显示成功；
6. OFF 页面不再出现“运行中”、暂停按钮或当前参与判断；
7. 昵称按群名片优先展示，头像失败时稳定降级且无破图；
8. 默认页面不出现 `AMBIENT`、`forced_observe` 等内部术语；
9. 浅色、深色和普通桌面宽度均可读；
10. 不改变现有外部插件优先和 Groupmate 后置处理语义；
11. 页面中不存在损坏图片占位符、被覆盖的顶部卡片或不可读的压缩表格；
12. 在约 1272 CSS 像素宽度下侧栏仍显示文字，主事件流关键六列可读。
