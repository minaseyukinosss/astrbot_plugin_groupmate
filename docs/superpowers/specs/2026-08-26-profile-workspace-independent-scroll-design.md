# 画像工作区独立滚动设计

## 目标

画像页在桌面端形成稳定的主从双栏工作区。浏览较长的成员目录时，右侧当前成员画像保持在原位置；阅读较长画像时，左侧目录位置也不受影响。

## 当前问题与根因

`.profile-member-list` 已声明 `overflow-y: auto`，但祖先 `.profile-browser` 只有 `min-height: 35rem`，没有受控高度。成员列表会继续撑高整个双栏容器，因此浏览器滚动的是页面主区域，而不是左栏列表。右侧详情随同一页面滚动位置移动，导致在列表底部选择成员后难以从画像顶部开始查看。

## 桌面端布局

- `.profile-workspace` 占用运行页面当前剩余的可视高度，并允许其网格子项收缩。
- `.profile-browser` 使用受控高度，目标为当前视口减去 AstrBot 顶部栏、页面标题、群体画像摘要和页面间距后的可用空间。
- 双栏工作区最低高度为 `35rem`；视口不足时由页面本身正常滚动，不压缩为不可用的小面板。
- 左侧 `.profile-directory` 与右侧 `.profile-detail-host` 都设置 `min-height: 0`，确保各自滚动容器可以收缩。
- 左侧只有 `.profile-member-list` 使用纵向滚动。成员数、刷新按钮和搜索框保持可见。
- 右侧 `.profile-detail-host` 使用独立纵向滚动，画像内容不再决定整个双栏的高度。
- 不设计自定义滚动条，沿用系统滚动行为和主题。

## 交互行为

- 用户切换成员后，右侧详情滚动位置立即回到顶部，再显示加载占位和新画像。
- 左侧成员列表滚动位置保持不变，方便连续查看相邻成员。
- 刷新画像不会强行改变用户当前的左右滚动位置；重新渲染整个工作区时遵循现有页面刷新行为。
- 键盘焦点、按钮选中态和现有可访问名称保持不变。

## 响应式行为

- `44rem` 以下继续使用上下布局。
- 窄屏下取消右侧独立滚动，详情随页面自然滚动，避免页面滚动与详情滚动嵌套。
- 窄屏成员目录保持现有最大高度，成员列表继续在目录内部滚动。
- 窄屏切换成员仍将详情区域自身的滚动位置归零，但不会强制整页跳到详情位置。

## 实现边界

- 修改 `pages/settings/styles/components.css` 中画像布局相关规则。
- 修改 `pages/settings/workspaces/profiles.js`，在选择成员时重置详情滚动位置。
- 不修改画像数据结构、查询接口、成员排序、搜索逻辑和视觉配色。
- 不引入新的依赖、滚动库或浏览器专用 API。

## 验收标准

1. 桌面宽度下，滚动左侧成员列表时右侧画像位置不变化。
2. 桌面宽度下，滚动右侧画像时左侧成员位置不变化。
3. 在右侧滚动到底部后选择另一成员，新画像从顶部开始显示。
4. 左栏标题、成员数、刷新按钮和搜索框在滚动成员列表时始终可见。
5. `44rem` 以下仍为上下布局，没有双重详情滚动区。
6. 原有选中态、搜索、加载态和错误态继续可用。

## 验证范围

- 增加页面契约测试，先证明当前 CSS 缺少受控高度和右栏滚动，并证明成员切换未重置详情位置。
- 修复后只运行画像页相关页面测试和静态差异检查，不执行全仓大型测试。
