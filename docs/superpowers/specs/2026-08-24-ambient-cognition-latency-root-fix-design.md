# AMBIENT 认知延迟根因修复设计

## 目标

修复普通群聊认知精准触发 10 秒超时的问题，不通过延长等待时间掩盖故障。闲聊判断必须在既有 8 秒有效期内完成；无法及时形成可靠判断时继续观察。

## 已确认根因

1. AMBIENT 窗口采用滑动截止时间，群持续活跃时会不断累积事件、话题和参与者。
2. 每次 AMBIENT 判断同时调用 `scene_interpreter` 与 `participation_assessor`，相同上下文被发送给同一 Provider 两次。
3. worker 固定 10 秒截止晚于 AMBIENT 的 8 秒有效期；即使模型之后返回，结果也会被判过期。
4. 旧诊断只记录总耗时，无法区分并发队列等待、Provider 等待和输入规模。

## 方案选择

采用“有界窗口 + 单次联合认知 + 总预算约束”。

不采用单纯提高超时：它会增加延迟，而且超过 8 秒的结果没有使用价值。

不采用保留两个 worker 后改为串行：它仍然发送两次相近输入，总耗时更差。

## 数据流

普通消息先进入确定性策略。需要 AMBIENT 理解时：

1. 观察窗口只保留最近 12 条事件、最近 4 个话题和最近 8 名候选参与者；始终保留最新项。
2. 构造一个 `ambient_social_assessor` 请求。模型可同时输出社交信号和一条 `participation_assessment`，但不能生成回复正文。
3. 本地 `IntentionEngine` 和 `ParticipationPolicy` 继续负责候选生成、阈值及最终是否参与，模型不直接获得发送权。
4. AMBIENT worker 的实际截止取配置值与当前剩余有效期中的较小值，永不越过 8 秒总预算。
5. 超时、模型失败或输出无效时保持降级观察。

## 可观测性

每个认知诊断增加：

- `queue_wait_ms`：等待 Groupmate 并发配额的时间；
- `provider_latency_ms`：真正等待 AstrBot Provider 的时间；
- `input_bytes`：发送给模型的结构化输入 UTF-8 大小；
- `timeout_ms`：本次实际使用的截止时间。

页面默认展示人类可读说明；原始字段仍只放在折叠的技术信息中。不得保存 Prompt 正文、模型响应正文或异常消息。

## 配置

撤回默认 20 秒。`cognition_timeout_seconds` 作为全局安全上限保留，默认 8 秒、范围 3–15 秒；AMBIENT 仍受剩余有效期的更严格限制。

## 兼容与迁移

- 旧 trace 缺少新增诊断字段时继续使用现有总耗时展示。
- 保留旧 worker 名称的页面映射，以便查看历史记录。
- 数据库 JSON 字段为向后兼容扩展，不修改既有表结构。

## 验证

只运行相关测试：

1. 持续活跃群聊的 pending window 永不超过三项上限；
2. AMBIENT frame 只请求一次联合认知；
3. 联合结果能同时产生社交信号和参与判断；
4. 实际 worker 超时不超过 AMBIENT 剩余预算；
5. 诊断字段不包含 Prompt、响应和原始异常消息；
6. 旧诊断与旧 trace 页面仍可展示。
