# AstrBot Groupmate 智能体设计规格

日期：2026-07-17  
修订：2026-07-22（精简收敛）  
状态：**现行生效**（以 [`2026-07-22-groupmate-v2-architecture.md`](./2026-07-22-groupmate-v2-architecture.md) 为准）  
目标环境：AstrBot 4.24+，通过 NapCat/OneBot v11 接入 QQ

## 1. 目标

构建可复用的 AstrBot 插件，使机器人表现为群聊伙伴：持续观察群聊、维护有边界的上下文、被叫到时可靠唤醒、判断何时适合主动参与，并按人格短回复，同时避免刷屏。

领域逻辑不写死爱弥斯专属关系；关系通过配置注入。默认人格可使用内置爱弥斯预设。

## 2. 已确认的产品决策

- 平台：QQ + NapCat/OneBot v11。
- 上下文：首次接触某群时尽力补拉最近约 100 条，之后吃实时事件。
- 主动发言：活跃群约每小时 3～6 条；直接唤醒不占用该额度。
- 图片：仅话题确实依赖时按需看图。
- 指令：AstrBot / 第三方指令始终旁路优先。
- 模型：小模型做自主插话门控，群聊天模型生成可见回复。
- **默认由 Groupmate 接管群聊 `@` / 回复 Bot**（`handle_native_wake=true`），并抑制 AstrBot 默认 LLM，避免双回复。

## 3. 明确不在范围内（已舍弃）

表达学习、反思合并、发送后自动记忆写回、疲劳状态机、表情包、影子评测与 WebUI 控制中心。详见精简架构文档。

## 4. 架构

事件驱动的单智能体工作流 + 端口适配器。LLM 不拥有运行循环；调度、额度、幂等、持久化由代码控制。

### 4.1 平台外壳

- AIOCQHTTP 群消息观察器
- `on_llm_request`（仅在关闭原生接管时补充上下文）
- 管理命令：status / pause / resume / reset
- 启动与终止生命周期

### 4.2 每群 Actor

串行邮箱：收消息、工作窗口、话题防抖、续聊窗口、频率限制；同群同时只跑一条决策/回复路径。

### 4.3 认知工作流

1. `OBSERVE`
2. `RECALL`（检索已有记忆条目；现行默认几乎不写回）
3. `GATE`（直接唤醒跳过模型；候选走决策模型）
4. `VISION`（可选）
5. `PLAN` → `GENERATE` → `GUARD` → `SCHEDULE` → `SEND`

无 `LEARN` / 影子观察阶段。状态迁移记 `decision_id` + 原因码，不存模型思维链。

## 5. 触发路由

| 种类 | 行为 |
|---|---|
| 原生直接唤醒（`@` / 回复 Bot） | 默认立即回复 |
| 别名直接呼叫 | 立即回复 |
| 续聊 | 直接呼叫成功后，同发送者在窗口内无需再叫名字 |
| 别名提及 / 普通候选 | 防抖后决策门控 |
| 指令 / Bot 自身 / 忽略 | 旁路或观察 |

决策模型输出：`action`（respond|ignore）、`confidence`、`reason_code`、`contribution`、`needs_vision`、`urgency`、可选 `target_message_id`。结构无效或失败则沉默。

## 6. 话题与时机

- 防抖：随机约 4～8 秒，且不超过 `topic_max_seconds`（默认 12）。
- 候选 TTL：约 20 秒。
- 新的直接唤醒取消等待中的主动插话。
- 拟人延迟有上限；直接唤醒延迟更短。
- 发送可拆为最多约 2 段短消息。

## 7. 记忆与关系

- 工作记忆：内存环形窗口（约 100 条）。
- 持久化：消息索引、决策轨迹、Outbox；记忆表保留检索能力，但不做自动伪学习写回。
- 称呼与关系：配置项 `relationships`（QQ → 关系 / 称呼），人工配置优先。

## 8. 人格与 Guard

人格分层：身份事实、关系边界、语言风格、输出硬约束。动态群上下文以用户侧内容注入，不污染稳定系统提示。

发送前确定性校验：长度、句数、客服腔、决策旁白、系统词、近期重复等。可修复的风格问题最多 repair 一次；安全/过期/重复等问题直接放弃。

## 9. 端口

`PlatformPort`、`HistoryPort`、`DecisionModelPort`、`GenerationModelPort`、`VisionPort`、`MemoryRepository`、`PersonaProvider`、`TraceSink`、`Clock`。

## 10. 配置与运维

AstrBot 插件配置页（`_conf_schema.json`）为唯一配置源。不单独存 Provider 密钥。

故障原则：决策失败沉默；历史补拉失败继续吃实时事件；关闭时取消防抖并关库。

## 11. 测试与成功标准

- 单元 / 契约测试覆盖触发、防抖、续聊、Guard、工作流 fail-closed。
- 不依赖真实 QQ / 网络。
- 成功：指令不双回复；直接唤醒可靠；主动插话有额度；模型故障不瞎聊；爱弥斯硬约束可测。

## 12. 首版范围

包含：群观察、Actor、工作窗口与历史补拉、触发与续聊、决策门控、按需看图、生成与 Guard、拟人投递、SQLite、配置与管理命令。

不包含：语音视频理解、向量库、定时问候、工具循环、多智能体、以及第 3 节列出的已舍弃项。
