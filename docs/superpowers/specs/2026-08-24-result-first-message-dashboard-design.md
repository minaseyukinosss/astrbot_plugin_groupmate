# 结果优先的消息看板设计

## 目标

在不改变运行中心现有外壳、配色、事件表格和右侧详情抽屉的前提下，让管理员首先看懂两件事：Groupmate 正式运行时会不会回复，以及为什么。技术诊断继续保留，但默认折叠，不与业务结论争夺注意力。

## 范围

本次只调整消息事件流及其详情投影：

- 事件列表中的决定摘要。
- 右侧“完整处理链路”详情的信息层级。
- 经过校验的模型判断理由与一条关键证据的安全投影。
- 模型异常、外部插件接管和非模型策略通道的展示回退。

不调整运行中心其他模块、导航、主题、群选择、实时刷新机制、认知策略、Governor 阈值、回复生成与发送行为。

## 设计原则

1. 结论先于过程：首屏先回答“会不会回复”，再说明原因。
2. 一条证据足够：默认只展示模型引用的最新一条有效消息。
3. 不重复同一结论：参与判断、SHADOW 前判断、最终结果不再以多组同义字段同时出现。
4. 技术信息后置：模型名称、耗时、请求大小、截止时间、阶段时间线和诊断码默认折叠。
5. 不展示原始模型输出、Prompt 或推理过程，只展示本地已校验的结构化结论。

## 信息架构

### 事件列表

保留当前时间、消息、处理路径、理解、决定、最终结果的表格结构，不重做运行中心。

“决定”列改为结果优先摘要：

- 主行：`正式运行会回复` 或 `正式运行不会回复`。
- 状态：`准备回复`、`继续观察`、`稍后再判断` 或异常状态。
- 次行：模型理由；没有模型理由时使用现有策略理由。

“Groupmate 的理解”列只保留一句场景摘要；认知模块失败时显示警告，不重复显示参与结论。

### 右侧详情

详情仍以当前消息的成员、头像、内容和时间开头。其后首先出现“处理结果”区：

- 醒目的正式运行结论。
- 当前动作标签，例如“继续观察”。
- 一句简短判断原因。
- 一条关键证据：成员昵称、头像（可用时）和消息摘要。
- 候选回复仅在确实生成时显示。

“收到的消息”和“处理路径”继续保留。原“Groupmate 的理解”“策略判断”“最终结果”中重复字段合并到处理结果区。

以下内容改为折叠展示：

- 处理阶段。
- 认知模块诊断。
- 认知后端、模型名称、耗时、请求大小、截止时间。
- 原始策略通道、候选来源、诊断码、链路历时与更新时间。

## 数据流

模型响应仍先经过 `DeepSeekCognitionClient` 解析和 `DirectAmbientWorker` 本地校验。只有成功创建的 `participation_assessment` 可以进入消息看板。

`MessageTraceRepository.record_evaluation` 从 `ShadowEvaluation.cognitive_observations` 中选择当前 AMBIENT 窗口有效的 `participation_assessment`，投影一个小型 `judgement` 对象：

- `source`: `model`、`policy` 或 `external`。
- `status`: `accepted`、`unavailable` 或 `not_required`。
- `decision`: `speak` 或 `silence`。
- `would_reply`: 最终策略在正式运行下是否回复。
- `label`: 页面使用的简短动作标签。
- `reason`: 最长 80 个字符的已校验模型理由。
- `evidence`: 一条已存在消息记录的安全摘要。

证据只根据 observation 的 `evidence_event_ids` 查找当前群的 `message_traces` 记录，复用记录中已经完成昵称、头像、@、图片和文本裁剪的公开摘要。找不到证据记录时省略证据块，不回退展示内部事件 ID。

为支持恢复后的投影，`safe_cognitive_observation` 允许持久化最长 80 个字符的 `reason`，其余字段仍使用白名单；不增加原始响应、错误文本、Prompt、API Key 或 Chain-of-Thought。

## 状态与回退

- 模型判断成功：展示正式运行结论、模型理由和关键证据。
- 模型建议沉默：这是正常业务结果，显示“正式运行不会回复”，不标记为降级。
- 模型失败或输出未采用：首屏显示“模型判断未采用”和现有安全诊断解释；不得伪装成正常模型理由。
- DIRECT_FAST 或 CONTINUATION：展示策略直接得出的结论与依据，标记为策略判断，不显示模型卡片。
- 外部插件接管：展示“交给外部能力”，不显示 Groupmate 参与判断。
- SHADOW：主结论仍表达正式运行是否会回复；发送状态另以“SHADOW 未发送”简短注明。
- 证据缺失：结论与理由仍显示，证据区域不渲染空占位。

## 视觉与交互

沿用 `tokens.css` 的中性表面、绿色主状态、黄色警告和现有字号/圆角。新增结果区使用留白、字重和分隔线建立层级，不创建嵌套卡片，不引入新的颜色体系、阴影或装饰动画。

在窄屏详情中，结论、标签和原因按自然纵向流排列；证据消息允许换行，昵称和头像不被压缩成竖排。技术折叠区继续使用原生 `details`，保持键盘可访问性。

## 测试

只运行与本次变更相关的聚焦测试：

- 消息投影契约：模型说话、模型沉默、模型失败、缺失证据、策略通道与外部接管。
- 隐私裁剪：投影不含原始响应、Prompt、内部事件 ID 或远端错误内容。
- 页面 presenter：主结论、状态、理由和回退文案。
- 页面 DOM 契约：详情首屏结果优先，技术数据位于折叠区，重复字段不再渲染。
- 明暗主题使用现有令牌，不新增主题分支。

不调用线上模型，也不运行无关全量套件。

## 验收标准

管理员在事件列表中无需点开即可知道正式运行是否会回复及简短原因；点开详情后，第一屏能看到同一结论、明确原因和一条关键证据。正常的模型沉默不会再显示成“认知降级或参与条件不足”。耗时、输入大小和截止时间默认不可见，但仍可从技术信息中展开排查。
