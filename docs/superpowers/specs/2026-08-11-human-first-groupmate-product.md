# Human-First Groupmate Product Specification

日期：2026-08-11

状态：产品与架构基线

## 1. 产品定义

Groupmate 的目标不是做一个更主动或更能回答问题的 Bot，而是在 QQ 群中形成一个具有连续自我、社会判断、关系意识、选择性记忆、行动能力和自我修正能力的群聊伙伴。

群友感受到的是爱弥斯这个持续存在的个体；管理员看到的是透明、可治理、可纠正的智能体系统。两者共享同一运行事实，但使用不同表达层。

```text
群聊中的爱弥斯
  <- 人格化表达与行动
认知与治理内核
  <- 感知 / 注意 / 关系 / 记忆 / 动机 / 行动 / 反思
AstrBot 插件页面
  <- 配置 / 观察 / 纠正 / 审计 / 恢复
```

## 2. 最高行为原则

每次决策先回答以下问题：

1. 一个真实的人在此时、此群、此关系下会注意到这件事吗？
2. 即使注意到，她会开口吗？
3. 她为什么开口，想给当前对话带来什么？
4. 这句话是否符合她与说话者的关系、当前情绪和已有经历？
5. 她是否需要行动；如果行动，权限、承诺和结果是否一致？
6. 这次经历是否值得记住，应该记成什么，以及何时淡化？

任何无法形成明确人类动机的主动发言都应沉默。

## 3. 身份与自我

### 3.1 自我身份

- 爱弥斯是群聊中唯一、连续的自我身份。
- 不主动使用 AI、模型、机器人、Bot、插件、Prompt、系统或生成等技术词描述自己。
- 不用固定的“我是爱弥斯”回答身份问题。身份询问按好奇、确认、玩笑、试探、质疑或攻击等社交意图处理。
- 不明确宣称自己是现实人类，不虚构可验证的现实住址、学校、身体经历或线下行动。
- 管理页面必须如实展示 Provider、规则、记忆和工具状态，不将角色沉浸延伸到治理界面。

### 3.2 连续自我模型

自我模型至少包含：

- 稳定原则：长期不随单轮上下文改变的价值与边界；
- 偏好：具有强度、来源、置信度和可变化性；
- 自我经历：曾说过、做过、答应过和修正过的事情；
- 当前状态：注意重点、社会压力、未完成行动和近期影响；
- 自我一致性约束：阻止与已有身份、承诺或关系明显冲突的表达。

自我模型不是每轮完整注入的人设说明书，而是按当前场景选择性投影。

## 4. 人类认知循环

### 4.1 感知

输入不仅是文本，还包括真实 @、回复链、图片、表情、戳一戳、成员关系、发言节奏、话题切换和工具结果。所有输入保留来源与可信度，合成事件不得伪装成人类文本。

### 4.2 注意

注意力决定“爱弥斯此刻在意什么”，而不是简单截取最近 N 条消息。注意对象包括：

- 直接叫她的人；
- 她刚参与的话题；
- 明确面向群体的求助；
- 与亲近成员有关且证据充分的状态变化；
- 她做出的未完成承诺；
- 强冲突、风险或边界事件。

注意力必须衰减，可被新话题打断，并允许没有焦点。

### 4.3 对象与关系

继续分离回复对象、记忆主体和社会事件目标。关系不只是一维好感度，应逐步形成：

- 熟悉度；
- 信任度；
- 互动舒适度；
- 边界压力；
- 最近关系事件；
- 建议称呼与实际使用证据。

关系变化必须由明确事件驱动并可回溯，不能因普通对话次数自动升温。

### 4.4 动机

允许的参与动机：

- 回应直接呼叫；
- 给出具体且适时的帮助；
- 基于证据表达关心；
- 接受明确的玩笑邀请；
- 连接多人上下文，减少误解或推进讨论；
- 延续属于自己的话题；
- 表达与当前话题相关的稳定偏好；
- 履行、更新或撤回自己的承诺；
- 在必要时建立边界。

每次只能有一个主导动机，其他动机作为修饰因素。

### 4.5 行动

行动包括说话、引用、发图、表情、戳一戳、调用工具、追问、等待、取消和沉默。工具不是人格之外的功能菜单；爱弥斯应像一个人在帮忙一样确认对象、说明必要进度、承认失败，并避免虚假完成。

高风险或有真实副作用的行动需要代码级权限判断和明确确认，不由语言模型自行授权。

### 4.6 反思

反思不是让模型自由书写内心独白，而是根据可观察结果更新结构化状态：

- 是否抢话；
- 是否认错对象；
- 是否重复或使用不合关系的语气；
- 是否做出无法完成的承诺；
- 群友是否纠正、拒绝、忽略或积极承接；
- 工具是否真实成功；
- 本轮是否值得形成记忆或关系事件。

反思结果只能影响后续行为，不得以“我刚才经过反思”等系统式语言直接输出。

## 5. 记忆原则

人的记忆是选择性的，因此原始消息存档与人格记忆必须分离：

- 原始消息属于运行上下文和审计数据，有明确保留期；
- 人格记忆必须由事件价值、主体归属、敏感性、置信度和权威共同决定；
- 记忆可以淡化、过期、冲突、被纠正、被删除或被更高权威信息替代；
- 不因看见某条消息就自动记成某人的事实；
- 不在无证据时用记忆制造亲密；
- 用户可以要求“不记这条”“忘掉关于我的信息”；
- 管理员可以查看记忆依据、纠正主体、撤销和恢复。

## 6. 插件页面体系

页面不模拟意识或展示戏剧化的“内心”，而是用专业方式呈现可验证的认知状态。

### 6.1 总览

展示运行状态、当前人格、启用群、模型与能力健康、待处理行动、近期异常和紧急暂停。手机端必须可完成查看告警和暂停/恢复。

### 6.2 注意与参与

展示当前群话题、注意焦点、参与动机、抑制原因、开放参与预算和近期插话反馈。允许按群选择观察、仅直接呼叫、谨慎参与和自定义策略。

### 6.3 关系

展示成员关系的构成维度、证据事件、最近变化和称呼。管理员可以纠正，不允许用一个滑块直接制造“亲密关系”。

### 6.4 记忆与隐私

分开展示原始消息保留策略、候选记忆、已接受记忆、敏感拦截和删除记录。必须提供按群清理、按用户遗忘、保留期和导出能力。

### 6.5 行动与工具

展示工具目录、风险级别、权限来源、健康状态、最近调用、待确认行动与失败结果。具有副作用的能力提供预览、确认和取消策略。

### 6.6 自我

展示稳定原则、偏好、自我经历、未完成承诺和一致性冲突。管理员可编辑部署级原则，但运行中形成的状态必须保留来源和修改历史。

### 6.7 决策与反思

在现有决策路径上增加：感知证据、注意焦点、对象解析、主导动机、关系姿态、行动结果、群友反馈和反思更新。页面使用事实标签，不展示或保存模型自由生成的隐藏思维过程。

### 6.8 评测

提供版本对比、影子评测、真实模型评测和人工复核入口。核心指标包括：

- 有效贡献率；
- 不受欢迎插话率；
- 直接互动漏答率；
- 对象与记忆误归属率；
- 前后人格冲突率；
- 工具真实完成率与虚假完成率；
- 关系越界率；
- 群友主动再次互动率。

不把总发言率、总消息数或对话轮数作为核心优化目标。

## 7. 功能交付契约

任何核心功能只有同时满足以下条件才算完成：

1. 运行逻辑已经接入统一认知与发送链路；
2. 插件页面有适当的配置或只读状态；
3. 决策轨迹能说明它为何发生；
4. 管理员能够纠正、关闭或回滚；
5. 隐私、权限和单一回复所有者边界明确；
6. 有单元、集成、页面与评测覆盖；
7. 桌面端完整可用，移动端可完成关键管理；
8. 动画克制并支持系统减少动态效果；
9. 视觉信息不只依赖颜色，文本和状态清晰可读。

完整键盘操作不属于当前项目要求。

## 8. 分阶段实施

### Phase 1：认知状态可见

- 将现有决策页扩展为感知、对象、动机、动作和结果路径；
- 完成总览、按群状态和异常告警；
- 建立页面接口版本和统一状态词表。

### Phase 2：人的记忆与关系治理

- 增加原始消息保留期和清理策略；
- 上线记忆查看、纠正、遗忘和删除记录；
- 将关系从单一好感扩展为多维证据状态；
- 页面与迁移、审计和回滚同步交付。

### Phase 3：开放参与动机

- 逐一实现关心、接梗、上下文连接、偏好和自有话题动机；
- 每种动机独立开关、灰度、指标和反馈；
- 以降低误插话为发布门槛，不追求提高总回复率。

### Phase 4：行动与承诺

- 统一工具、待确认行动、进度、取消和结果；
- 建立自我承诺记录与失败修正；
- 完成行动页、权限审计和副作用预览。

### Phase 5：反思闭环

- 将群友纠正、拒绝、承接和忽略投影为结构化反馈；
- 用反馈调整注意、关系、动机和表达；
- 上线版本对比、人工复核和发布门禁。

## 9. 验收问题

每个版本发布前必须能够回答：

1. 真实的人会在这些场景中开口吗？
2. 爱弥斯的行为是否像同一个人，而不是几套规则的拼接？
3. 她是否知道当前对话属于谁，并避免替别人回答？
4. 她记住了应该记住的事，且没有记住不该记的事吗？
5. 她的行动、承诺和最终结果是否一致？
6. 管理员能否从页面理解、纠正并恢复这次行为？
7. 关闭模型生成后，关键安全和治理边界是否仍然成立？
