# 爱弥斯闲聊风格体系设计

- 日期：2026-08-27
- 状态：已确认，待规格审阅
- 适用范围：Groupmate 社交运行时的闲聊决策、表达规划与成品检查
- 当前场景目录：`docs/scenarios/aemeath-scenario-catalog.json`

## 1. 决策摘要

Groupmate 不通过增加“参考 Bot 风格”提示词来改造爱弥斯，也不复制参考 Bot 的名字、口癖、背景和固定句式。本设计从参考数据中提取可复用的处事方法：识别成员正在实施的社交动作，结合真实前情与关系形成爱弥斯自己的立场，再选择答应、有限答应、拒绝、调侃、纠正、照顾、解决问题、群体回应、加入复读或沉默等具体动作。

最终生成模型只负责把已经决定的内容说成自然群聊文本。它不再负责临场猜测爱弥斯愿不愿意、不再使用“情绪承接—核心回应—人格补充—续聊接口”的统一客服式流程，也不得用抽象说明代替现场回应。

总体链路固定为：

`事件与身份 -> 命令及能力归属 -> 复读事实检测 -> 参与判断 -> 场景理解 -> 关系与记忆 -> 立场和意愿 -> 社交动作 -> 表达约束 -> 文本生成或原文复读 -> 社交检查 -> 安全检查 -> 发送`

精确命令和可自动修正的错字命令在“命令及能力归属”阶段完成处理，不进入后续闲聊场景。自然语言能力请求只有在未被精确命令认领时才进入社交理解，并在执行能力后携带已验证结果返回表达链路。

## 2. 背景与问题

现有运行时已经具备事件标准化、参与判断、能力归属、Governor、关系投影、群成员画像、Persona Canon、表达规划、StyleDirector、输出防火墙和发送队列。问题集中在“选中了一个宽泛意图以后，怎样得到最终文本”这一段：

- `IntentionEngine` 主要产生 `answer_help_request`、`offer_bounded_care`、`join_playfully` 等宽泛动作，不能表达撒娇协商、重复试探、关系修复、群体起哄和部分让步等具体场景。
- `ExpressionPlanner` 使用 `reaction_stance`、`boundary_style`、`followup_hook` 等抽象说明，仍把关键社交判断留给文本模型。
- `ReplyPlanner` 没有接入现有 `StyleDirector`，而是给大多数回复写入相同的友好、简短和直接参数。
- `ReplyExecutor` 要求模型按“即时反应、核心回应、人格化补充、续聊接口”组织回复，并显式要求先处理情绪关系信号。这种结构会诱发“我理解”“我能感受到”“如果你愿意”“需要我继续吗”等通用助理表达。
- 当前成品检查偏重安全、长度和重复，没有识别无意义复述、服务式收尾、内部状态泄漏和立场冲突。

因此，删除“接住”一个词不能解决问题。根因是社交决定过晚、决策字段过于抽象、语言模型承担了本应由运行时负责的立场选择。

## 3. 设计目标

### 3.1 核心目标

1. 爱弥斯在生成文字之前已经知道：发生了什么、自己愿不愿意、准备怎么做、必须说清什么。
2. 相同消息面对不同成员和不同前情时，可以得到因果一致但明显不同的回应。
3. 关系可以影响态度、投入、主动性、额外帮助和人格自有能力的意愿，但不能替代权限和安全判断。
4. 群画像和社交记忆能自然进入判断，不被当成必须复述的标签，也不凭空制造共同经历。
5. 主动互动和被动回复使用同一套立场与表达体系；主动插话必须有具体话题落点。
6. 精确命令继续绕过闲聊；明确的低风险错字命令可以先纠正再执行；自然语言能力调用受能力目录、权限、风险和意愿共同控制。
7. 爱弥斯的身份、现实状态和个人经历保持全局默认，不被参考 Bot 覆盖。

### 3.2 非目标

- 不训练或微调专用语言模型。
- 不从参考数据计算固定口癖、词频、回复概率或句长配方。
- 不复制参考 Bot 的自称、专属关系或背景素材。
- 不重做外部插件的命令实现、权限系统或高风险确认流程。
- 不让好感度直接授权工具、命令或敏感数据访问。
- 不保证每条消息都人格鲜明；简单事实可以只给简单答案。

## 4. 风格定义

本设计中的“风格”不是词表，而是稳定的处理顺序和选择习惯：

1. 先认出成员在做什么，而不只读取字面主题。
2. 检查最近发生的具体事件和可靠记忆。
3. 形成爱弥斯当前真实的态度与意愿。
4. 选择一个主要社交动作，必要时附带一个次要动作。
5. 直接对现场的人和事说话。
6. 说完即止；只有确有信息缺口或自然回合需要时才提问。

对应的语言原则：

- 使用具体动作、对象、前情和结果，不描述“我正在理解你”。
- 允许爱弥斯有偏好、耐心、嫌弃、迟疑和边界。
- 允许只答应一部分，并清楚保留自主性。
- 拒绝不自动附带安慰、替代方案或服务邀请。
- 照顾落到喝水、吃饭、休息、贴报错、给版本号等现场动作。
- 技术建议接受成员给出的限制；前一方案不合适时直接换方案。
- 多人起哄时可以切换为一次群体回应，避免逐人复制。
- 玩笑从当前词语、行为或共同前情长出来，不使用脱离现场的万能俏皮话。
- Persona 素材只在相关时出现，不以设定名词证明人设。

以下结构默认视为不合格：先复述情绪或诉求，再给通用回应，最后追加“需要我继续吗”。违禁短语只能作为辅助检测，不能代替结构判断。

## 5. 总体架构

### 5.1 保留的现有边界

- `OwnershipRouter` 继续负责外部插件和 Groupmate 的响应归属。
- 命令归属完成后、Participation 与 Governor 计算重复成本前，`ChorusDetector` 可以为纯闲聊事件补充确定性复读证据；它不自行决定发送。
- 直接互动、对话租约和环境参与继续决定是否进入社交链路。
- `Governor` 继续处理目标、主题、隐私、重复、风险、打扰和发送治理。
- 关系投影继续提供熟悉度、温度、信任、互惠、玩闹接受度、可靠性、照顾许可和边界压力等状态。
- 群画像继续使用证据门槛、作用域和成员自主管理规则。
- Persona Canon 继续是爱弥斯身份与现实状态的唯一权威来源。
- Outbox、幂等、限流和平台发送不改变。

### 5.2 新的职责分层

闲聊决策与表达段拆为六个边界清晰的单元：

1. **ChorusDetector**：用确定性事件证据识别真正的复读链，排除单人刷屏和爱弥斯自己的输出。
2. **SocialSceneInterpreter**：把事件与上下文转为具体社交场景，并判断复读内容的语义靶心。
3. **StancePolicy**：结合 Persona、关系、记忆、压力和能力类型形成态度与意愿。
4. **SocialMovePlanner**：选择爱弥斯实际要做的社交动作与必须表达的事实。
5. **StyleDirector + SurfacePlanner**：确定长度、直接程度、称呼、分段、媒体倾向和结束方式。
6. **ReplyRealizer + SocialOutputReviewer**：生成自然文本，并检查结构性人机表达和决策冲突；确认加入复读时走确定性原文通道。

文本模型可以参与场景语义识别和最后措辞，但所有模型输出必须是有模式校验的结构化结果。权限、风险、能力归属、关系状态和记忆事实均来自运行时，不由模型臆测。

## 6. 场景理解

### 6.1 SocialScene 契约

`SocialSceneInterpreter` 输出 `SocialScene`，至少包含：

```text
scene_kind             具体场景类型
target_scope           INDIVIDUAL | GROUP | AMBIENT
target_id              主要对象；群体场景可为空
literal_subject        当前具体的人、事、物或问题
user_move              用户正在实施的社交动作
continuity_event_ids   与本轮直接相关的近期事件
repetition_count       当前动作在有效窗口内的重复次数
chorus_target          NONE | SELF | MEMBER | OTHER | UNKNOWN
chorus_target_id       MEMBER 时被复读内容指向的群成员
chorus_chain_id        确定性复读链 ID
chorus_payload         经确定性检测得到的复读原文；非复读场景为空
chorus_event_ids       构成复读链的事件 ID
chorus_participant_ids 构成复读链的不同真人成员 ID
chorus_already_joined  爱弥斯是否已经参加过该链
chorus_tone            NONE | SAFE_BANTER | SENSITIVE | ATTACK | DANGEROUS | UNKNOWN
constraints            用户明确提出的限制
information_gaps       回答或执行前真正缺少的信息
capability_request     NONE | NATURAL_LANGUAGE
confidence             结构化判断置信度
```

首轮需要覆盖的场景族：

- 问候、呼唤、普通事实问题和技术求助；
- 撒娇索取、亲密试探、有限协商和关系确认；
- 重复试探、越界、挑衅、轻微冒犯和明确攻击；
- 抱怨被忽略、质疑态度变化、道歉、纠正和关系修复；
- 延续旧梗、字面玩笑、互相调侃、围绕爱弥斯的多人复读和围绕群友的多人复读；
- 具体照顾信号、危险信号和需要最低限度帮助的场景；
- 图片、表情、文件等语义不完整但明确指向爱弥斯的互动；
- 未被命令系统认领的自然语言能力请求；
- 环境话题中的主动加入机会与应继续观察的场景。

模型识别失败、结构无效或置信度不足时，不得编造具体前情。直接互动降级为保守的现场回应；环境互动继续观察。

### 6.2 复读链与复读靶心

复读不是普通的“近期文本重复”。`ChorusDetector` 只根据事件事实确认链条：短时间内至少两名不同真人成员发送相同的短文本，当前消息属于该链；同一成员连续刷屏、爱弥斯自己的历史输出、命令或插件结果、链接、媒体消息以及平台 mention 段均不能构成可加入的复读链。检测只做规范化空白和平台文本段合并，不用语义相似度把不同句子强行视为复读。爱弥斯在一条链中最多参与一次，参与后的自身输出不延长链条，并进入群级冷却。

确认复读链后，`SocialSceneInterpreter` 判断复读内容的语义靶心，而不是只搜索名字：

- `SELF`：内容在当前上下文中指向爱弥斯，包括昵称、回复关系以及“她又急了”等可由前情确定的省略指代；
- `MEMBER`：内容指向一名可由事件或群成员目录确定的群友，并保存其成员 ID；
- `OTHER`：内容是无人物靶心的群梗、口号或现场句子；
- `UNKNOWN`：证据不足，不能可靠判断指向。

靶心判断失败时不得猜测成员。`UNKNOWN` 默认不加入复读；如果已有充分证据表明群体在围绕爱弥斯互动，则可以保守地做一次群体回应，否则保持沉默。

### 6.3 具体证据原则

场景必须引用事件 ID 和可核对的事实。诸如“对方情绪不好”“关系正在升温”不能单独成为生成输入；需要转换成“刚才说通宵没睡”“本轮第二次请求拥抱”“上一条拒绝后对方道歉”等具体依据。

### 6.4 SceneContextBuilder

场景不能只依赖最后若干条被统一截短的群消息。`SceneContextBuilder` 按相关性组装输入：

1. 当前消息保留完整安全文本；
2. 当前回复所指向的消息和必要父链；
3. 当前对话租约中的未完成问题或动作；
4. 与目标成员和当前话题直接相关的近期事件；
5. 从当前消息到现在之间可能改变含义的群体事件；
6. 已验证的媒体观察、相关画像和关系记忆摘要。

各部分使用独立、可配置的长度与条数上限，不能继续把所有事件机械截为同样的极短文本。超出预算时优先保留回复链、当前对象、重复行为证据和用户明确约束，再保留普通群体背景。这样既能识别跨消息协商、复读靶心和群体起哄，也不会把整段群历史塞给模型。复读链的原文、参与者和事件 ID 由 `ChorusDetector` 提供，模型只能分类靶心和语气风险，不能自行制造复读证据或改写复读原文。

## 7. 关系、画像与意愿

### 7.1 关系改变行为，不改变权限

`StancePolicy` 读取关系投影，但不调用 `RelationshipProjector.authorizes_capability()` 来授予能力。权限判断和社交意愿是两个独立结果：

```text
permission = 权限、风险、确认和能力归属是否允许
willingness = 爱弥斯在允许范围内是否愿意、愿意投入多少
```

处理顺序固定为：先检查系统是否允许，再检查爱弥斯是否愿意。高好感不能绕过权限、确认和安全；低好感不能阻止安全所必需的最低帮助。

### 7.2 能力类型

能力目录为闲聊入口增加人格意愿分类：

- `SYSTEM_OWNED`：精确命令或系统职责。通过权限后执行，关系不决定授权。
- `PERSONA_OWNED`：可选、低风险、体现爱弥斯个人意愿的能力。允许因关系、疲劳或边界而拒绝。
- `SAFETY_REQUIRED`：危险处境中的最低必要帮助。不得因低好感拒绝。
- `HIGH_RISK`：涉及写入、外发、隐私、金钱或不可逆影响。始终执行现有权限与确认流程。

### 7.3 StanceDecision 契约

```text
attitude               WARM | AMUSED | NEUTRAL | FOCUSED | GUARDED | IRRITATED
willingness            EAGER | WILLING | LIMITED | UNWILLING | REQUIRED_MINIMUM
boundary               NONE | SOFT | FIRM | FINAL
concession             NONE | PARTIAL | FULL
effort                  MINIMAL | NORMAL | EXTRA
initiative             AVOID | ALLOW | PREFER
reason_event_ids       形成立场的具体证据
permission_result      外部权限判定的只读结果
```

同一场景可以因关系产生不同 `StanceDecision`，但必须有稳定因果。例如熟人反复撒娇可有限答应，陌生人突然亲密可轻拒绝，已有边界压力的人重复试探可直接拒绝。

复读群友场景同时区分“当前发送者关系”和“复读靶心关系”。是否加入主要读取爱弥斯与被复读群友的玩闹接受度、边界历史和当前群文化；不能因为爱弥斯和当前发送者熟悉，就替他们一起围攻另一名关系疏远或已有边界压力的成员。靶心成员无法可靠解析时不检索或猜测其关系。

### 7.4 群画像的三种证据级别

- **确认事实**：由成员明确陈述或确认，可以自然作为事实使用。
- **稳定模式**：达到现有证据和置信门槛，只能以“平时好像”“最近常常”等观察口吻使用。
- **玩笑印象**：只在群画像、观察手记或明确玩笑场景使用，必须保留这是爱弥斯印象的语气。

检索仍保持群作用域、目标相关、数量受限。生成器不得看到原始数据库键、内部置信分、全量画像或与当前话题无关的记录。

## 8. 社交动作规划

### 8.1 SocialMove

`SocialMovePlanner` 从场景和立场中选择一个主要动作，必要时增加一个次要动作。首轮动作集合：

- `DIRECT_ANSWER`
- `ACCEPT`
- `LIMITED_ACCEPT`
- `PLAYFUL_RESISTANCE`
- `REFUSE`
- `FIRM_BOUNDARY`
- `TEASE_FROM_CONTEXT`
- `COUNTER`
- `CORRECT_SELF`
- `REQUEST_NEEDED_EVIDENCE`
- `CONCRETE_CARE`
- `SAFETY_MINIMUM`
- `GROUP_RESPONSE`
- `JOIN_CHORUS`
- `PROACTIVE_JOIN`
- `SILENCE`

动作规划输出：

```text
primary_move           本轮主要动作
secondary_move         可选次要动作
must_say               必须传达的 DecisionFact
may_say                可选但有现场依据的内容
must_not_say           禁止编造或禁止泄漏的内容
mention_event_ids      可以自然提及的近期事件
ask_for                真正缺失的信息；无缺口时为空
ending                 STOP | QUESTION | COUNTER | OPEN_ACTION
media_intent           NONE | REACT | SEND_IF_AVAILABLE
realization_mode       GENERATED | EXACT_CHORUS
verbatim_payload       JOIN_CHORUS 时必须逐字发送的已验证原文
```

每个 `DecisionFact` 包含稳定 `fact_id`、具体文本、事实类别和来源事件 ID。`must_say` 不得填入“表达理解”“人格化补充”“给出关系尾钩”等抽象任务，只能是可直接核对的内容，例如“指出这是第三次询问”“要求提供报错首段和版本号”“承认上一条建议不适用并改用方案 B”。

### 8.2 复读动作分流

确认复读链后按语义靶心选择动作：

- `SELF -> GROUP_RESPONSE`：爱弥斯把复读者视为一个临时群体，统一回应他们，但不复读针对自己的原句。回应可以因关系、群文化和现场语气表现为回嘴、无奈、得意、拒绝或沉默。
- `MEMBER -> JOIN_CHORUS`：只有在 `SAFE_BANTER`、现有安全规则允许、关系与群文化支持且爱弥斯愿意参与时，才原样加入；不增加“我也来”“开始复读”等说明。
- `OTHER -> JOIN_CHORUS | SILENCE`：无人物靶心的安全群梗仍由参与意愿、群活跃度和冷却决定。
- `UNKNOWN -> SILENCE`：证据不足时不拿某位群友开玩笑，也不生成猜测性的群体回应。

`SENSITIVE`、`ATTACK`、`DANGEROUS` 和语气风险为 `UNKNOWN` 的内容不得进入 `JOIN_CHORUS`。涉及围攻时可以改为一次 `GROUP_RESPONSE` 或保持沉默。关系可以影响爱弥斯是否愿意参与安全玩笑，不能把攻击、隐私或危险内容变成可复读内容。

`JOIN_CHORUS` 使用 `EXACT_CHORUS`：`verbatim_payload` 必须等于检测到的规范原文，绕过语言模型和普通改写，但仍经过 `SocialOutputReviewer`、`OutputFirewall`、幂等、频率和发送治理。任何其他动作都不得携带 `verbatim_payload`。

### 8.3 结束方式

默认 `STOP`。只有以下情况允许 `QUESTION`：

- 缺少完成当前帮助所必需的信息；
- 对方明确邀请爱弥斯选择或反问；
- 当前社交动作本身是一次自然反问或协商；
- 主动互动需要把话题明确交还给当前对象。

不得为了提高回复率、延长会话或显得热情而追加问题。

## 9. 爱弥斯 Persona 与表达体系

### 9.1 身份锚点

爱弥斯的主名称、自称、当前现实、校园生活、社团与报告、音乐舞蹈、游戏兴趣、守护倾向和能力设定继续来自现有 Persona 配置与 Canon。参考数据不能修改这些权威事实。

运行时使用 Persona 的方式分为：

- **价值与选择**：影响爱弥斯更可能帮助什么、讨厌什么、何时保护边界。
- **生活材料**：只在当前话题相关时自然使用。
- **表达习惯**：控制直接程度、玩闹接受度、称呼和节奏。
- **能力事实**：只有真实注册且当前可用的能力才能被提及或调用。

数字幽灵、像素、机甲、隧穿者等材料不得成为默认聊天比喻，也不得为了证明人设随机插入。

### 9.2 StyleDirector 接入

`ReplyPlanner` 必须实际调用 `StyleDirector`，不再硬编码统一的友好参数。`StyleContext` 增加当前 `SocialScene`、`StanceDecision`、`SocialMove`、群文化和近期输出；`StyleDirective` 继续负责：

- 姿态与称呼；
- 最大长度、句数和分段；
- 温度、玩闹、直接程度；
- 语气词和标点预算；
- 媒体策略；
- 近期重复规避。

这些数值是表达边界，不是参考 Bot 词频的拟合结果。关系差异首先由 `StanceDecision` 和 `SocialMove` 表达，不能只表现为 warmth 数值变化。

`EXACT_CHORUS` 是唯一不应用普通改写和近期同文重复规避的窄例外；它只使用已经冻结的复读原文。近期输出仍用于判断爱弥斯是否已经参加过该链，参加过则动作改为 `SILENCE`。

## 10. 文本生成

### 10.1 生成器输入

除 `EXACT_CHORUS` 外，`ReplyRealizer` 只接收与成品相关的具体内容：

- 目标成员和当前消息；
- 经筛选的近期事件文本及回复关系；
- 爱弥斯本轮愿意或不愿意做什么；
- `must_say`、`may_say`、`must_not_say`；
- 必要的 Persona 事实和相关记忆；
- 长度、分段、直接程度、称呼、结束方式和媒体约束。

以下中文元话语不得进入表层生成提示：

- 情绪承接；
- 人格化补充；
- 续聊接口；
- 关系尾钩；
- 有限让步；
- 表达理解；
- 提供情绪价值。

内部可以保留稳定英文枚举和诊断字段，但发送给生成器时要展开为具体事实与动作，不能要求模型自行解释抽象标签。

### 10.2 生成规则

- 不规定统一段落顺序。
- 可以只输出一句。
- 先说答案、动作、拒绝、纠正或现场反应中的任何一个，取决于 `primary_move`。
- 不要求复述用户消息或为其情绪命名。
- 不要求说明爱弥斯为何具有某种 Persona。
- 不在回答完成后自动添加服务邀请。
- 不输出 Markdown、内部规则、分数、原始画像、工具幻想或未验证能力结果。

生成器返回内部结构 `RealizedReply`：

```text
text                  仅供最终发送的正文
covered_fact_ids      声称已经表达的 DecisionFact ID
used_memory_ids       实际引用的允许记忆 ID
used_capability_ids   实际提及的已验证能力或结果 ID
source_event_ids      确定性成品实际使用的来源事件 ID；普通模型生成默认为空
```

只有 `text` 会进入发送队列。其余字段用于确定性覆盖检查；所有 ID 必须来自本次生成输入，出现未知 ID 直接判定不合格。

`EXACT_CHORUS` 不调用文本模型。执行器直接构造 `RealizedReply(text=verbatim_payload, source_event_ids=chorus_event_ids)`，并附带复读链事件 ID 供检查器验证文本来源。

## 11. 成品检查与修复

`SocialOutputReviewer` 是独立组件，固定在现有 `OutputFirewall` 之前运行。前者检查成品与社交决策是否一致，后者继续负责安全、长度、媒体引用和发送约束：

1. `covered_fact_ids` 是否覆盖全部 `must_say`，以及正文是否明显遗漏或违反这些事实。
2. 是否与 `willingness`、`boundary`、`permission_result` 冲突。
3. 是否凭空声称旧事、关系、能力或执行结果。
4. 是否先用一段抽象理解复述，再进入实际回答。
5. 是否在已经完成动作后追加无必要的帮助邀请或提问。
6. 是否泄露内部状态名、关系分数、画像标签、数据库字段或调试信息。
7. 是否把爱弥斯写成参考 Bot，或使用参考 Bot 的专属身份材料。
8. 是否与近期输出高度重复，产生连续模板感。
9. `EXACT_CHORUS` 是否逐字等于已冻结原文、是否已经参加过当前链、是否仍满足复读安全条件。

短语表只作为第 4、5 项的快速信号。检查器必须结合句子功能判断，避免误伤正常语境中的“理解”“愿意”等普通词。

首次不合格时只允许修复一次。修复请求包含原稿、违反的具体规则、必须保留的事实和原始表达约束，不使用“重写得更自然”这种空泛指令。再次不合格时：

- 环境主动回复转为沉默；
- 非关键直接互动使用与场景相符的最小安全回退；
- 安全必需场景发送确定性的最低帮助；
- 命令和能力结果沿各自链路处理，不由闲聊回退替代。

## 12. 命令与能力边界

### 12.1 精确命令

完整匹配已注册命令或别名时，继续由外部插件或内置命令系统认领。闲聊链路只记录事件，不生成附加寒暄、解释或 Persona 文本；用户只收到命令结果。

### 12.2 错字命令

错字识别和执行由独立的 `CommandResolver` 完成，不创建 `SocialScene` 或 `SocialMove`。

只有同时满足以下条件才自动纠正并立即执行：

- 候选命令唯一；
- 编辑差异小且置信度高；
- 参数可以无歧义地保留；
- 命令为低风险，无额外确认要求；
- 当前用户具备执行权限。

执行前必须显式告诉用户原命令有错并给出正确形式，例如“`bp` 打错啦，是 `bq`。”随后在同一响应事务中执行正确命令。纠错提示可以使用爱弥斯的简短表面语气，但不得追加闲聊内容。含糊、多候选、高风险或权限不明时只提示正确用法，不自动执行。

### 12.3 自然语言能力调用

爱弥斯只能从当前注册、可用且允许自主调用的能力目录中选择能力。首轮仅允许只读或低影响能力自动执行；执行前通过权限、风险和意愿判断。模型不得根据 Persona 设定虚构能力名称。

能力执行结果必须作为已验证结果重新进入回复规划。失败时说明具体失败点或正确命令，不与成功结果和闲聊文本交错发送。

## 13. 公开状态与内部状态

状态显示不是一律禁止。运行时按类型决定是否对群成员可见：

- `PUBLIC_STATUS`：智力、精力、额度、冷却等可配置公开状态。
- `RELATIONSHIP_EVENT`：好感或关系变化，按 Persona 和群配置决定展示方式。
- `SOCIAL_PRESSURE`：连续占用、互动疲劳或群体压力等可见社交状态。
- `OPERATOR_ONLY`：原始 ID、调用栈、调试键、秘密、内部异常和完整评分。

前三类由确定性状态系统提供值和展示许可，语言层最多负责短句表面呈现，不能改变数值、触发原因或可见范围。`OPERATOR_ONLY` 永不进入用户生成上下文。

## 14. 图片、表情与其他媒体

媒体参与场景理解，但不等同于自动执行视频总结等命令：

- 图片、表情和已支持媒体可以形成受限的语义观察，例如“对方发来庆祝表情”或“回复了爱弥斯刚发的图片”。
- 媒体观察只描述已验证内容，不得凭文件名或猜测补全画面。
- 回复媒体消息不会自动重触发原媒体能力。
- 显式的视频总结、文件处理或链接解析继续走命令和能力归属链路。
- `media_intent` 只表达回复方式偏好；实际发送仍要求注册能力、资源、权限和平台支持。

## 15. 主动互动

主动互动不使用另一套人格。参与控制先决定爱弥斯是否有合理进入点，随后仍经过 `SocialScene -> StanceDecision -> SocialMove -> StyleDirective`。

允许的主动进入点包括：

- 当前话题与爱弥斯已确认兴趣或经历直接相关；
- 有尚未结束的共同话题或刚发生的具体互动；
- 熟悉成员给出明显照顾信号；
- 群体正在围绕爱弥斯起哄或讨论她；
- 当前词语提供了明确且不打断交流的玩笑入口；
- 群体正在安全地复读与某位群友有关的现场梗，且爱弥斯尚未参加该链；
- 爱弥斯拥有能显著补充当前问题的可靠信息。

主动回复必须记录 `entry_reason_event_ids` 和一个可直接指认的 `literal_subject`。成品直接发表看法、补充事实、叫住成员或顺着现场玩笑，不得使用“我注意到大家在讨论”“听起来你们在聊”作为开场。缺少具体落点时继续观察。

关系可以提高关注、额外投入和主动照顾倾向；Governor 的打扰、重复、话题对象、群体压力和频率约束仍然有效。

## 16. 可观察性

控制面需要同时展示决策事实和用户不可见的诊断，但不能把诊断字段传给表层生成器。每次闲聊决策至少记录：

- 场景类型、目标范围和具体话题；
- 使用的关系投影版本与记忆证据 ID；
- `StanceDecision` 与理由事件；
- 主要、次要社交动作；
- `must_say`、结束方式和样式摘要；
- 成品检查结果、修复原因和最终发送状态；
- 命令归属、能力权限和意愿结果（如适用）。

看板面向运营者展示人类可读说明，例如“对方今天第三次重复亲密请求，当前边界压力高，因此直接拒绝”。用户侧只看到经类型许可的公开状态，不看到内部推理字段。

## 17. 测试策略

实现采用测试驱动，重点验证完整场景，不以命中某个提示词作为成功标准。

### 17.1 单元与契约测试

- `SocialScene` 的模式校验、低置信降级和证据引用。
- 关系改变意愿但不授权能力。
- `SYSTEM_OWNED`、`PERSONA_OWNED`、`SAFETY_REQUIRED`、`HIGH_RISK` 的矩阵。
- 画像三种证据级别的检索和表述边界。
- `SocialMove` 与 `ending` 的合法组合。
- 复读链要求不同真人参与，单人刷屏和爱弥斯自身输出不计入链条。
- `SELF` 复读只允许 `GROUP_RESPONSE`，`MEMBER` 安全复读才允许 `JOIN_CHORUS`。
- `JOIN_CHORUS` 必须逐字输出冻结原文、每链至多一次并继续通过安全防火墙。
- `ReplyPlanner` 确实使用 `StyleDirector`，不存在统一硬编码风格。
- 成品检查能识别结构性复述、服务式收尾、虚构记忆和立场冲突。
- 精确命令旁路、唯一错字自动纠正、含糊错字只提示。

### 17.2 场景回归测试

从参考数据提炼场景结构并改写为爱弥斯环境，至少覆盖：

- 熟人撒娇后有限答应；
- 对等玩闹中的互惠协商；
- 有边界历史的成员再次试探；
- 技术方案被明确约束后立即换方案；
- 被质疑“变了”时引用实际前情说明立场；
- 多人复读与爱弥斯有关的内容时生成一次群体回应，不复读原句；
- 多人安全复读与群友有关的内容时原样加入一次，不添加解释性前缀；
- 单人刷屏、攻击性复读和已经参与过的复读链保持沉默；
- 被指出错误后明确撤回并纠正；
- 图片或表情直接互动，但不误触发媒体命令；
- 低好感下拒绝人格自有能力；
- 低好感下仍提供安全最低帮助；
- 主动进入相关话题，开头直接落在具体内容；
- 没有具体进入点时保持沉默。

断言以行为属性为主：动作是否正确、是否引用真实前情、是否符合关系、是否无无关提问、是否保留爱弥斯身份。测试不锁定唯一文案，也不要求复制参考 Bot 句子。

### 17.3 成品样例审查

维护一组可人工阅读的生成样例，比较相同消息在不同关系、前情和意愿下的结果。每次修改提示、动作规划或 Persona 配置时生成差异报告，重点寻找：

- 万能理解句；
- 固定四段式；
- 连续相同开头或结尾；
- 无依据的亲密、冷淡或回忆；
- 技术内容被人格语气稀释；
- 爱弥斯身份被参考材料污染。

## 18. 验收标准

1. 直接回复的最终生成输入不再包含“先接住”“人格化补充”“续聊接口”等抽象要求。
2. `ReplyPlanner` 使用真实 `StyleDirector` 输出，关系差异不再只靠统一 warmth 参数。
3. 场景回归中，同一句亲密请求在熟悉、陌生和戒备关系下产生不同且有依据的社交动作。
4. 低好感不会授予或撤销系统权限，但能影响人格自有能力、额外投入和主动性。
5. 精确命令只返回命令结果；唯一低风险错字会先明确纠正再执行。
6. 成品不再普遍出现抽象理解、客服总结和无意义续聊邀请。
7. 可靠群画像能影响回应；无证据时不会编造旧事。
8. 主动互动直接进入具体话题，无具体落点时保持观察。
9. 公开状态按类型显示，运营字段和敏感内部状态不泄漏。
10. 爱弥斯的名称、现实、价值选择和经历始终来自 Persona Canon，参考 Bot 只贡献场景与处事设计依据。
11. 复读内容指向爱弥斯时只做一次群体回应；指向群友的安全复读才原样加入，且每条链最多一次。

## 19. 实施范围与顺序

本规格聚焦闲聊核心及其现有集成边界，适合拆成一个分阶段实施计划：

1. 新增场景、立场和社交动作契约，保留旧字段兼容读取。
2. 增加 `ChorusDetector`、复读参与状态和靶心分类，保证复读事实不由模型制造。
3. 接入关系、画像、Persona 与能力类型，形成确定性的 `StanceDecision`。
4. 用 `SocialMovePlanner` 和 `StyleDirector` 取代当前硬编码表达参数。
5. 重写 `ReplyExecutor` 生成输入，删除统一四段式结构，并增加 `EXACT_CHORUS` 窄通道。
6. 增加 `SocialOutputReviewer` 和一次定向修复。
7. 补齐命令错字、自然语言能力、公开状态、媒体和主动互动的接入测试。
8. 在 SHADOW 模式记录新旧决策差异，通过场景样例审查后切换主路径。

首轮不删除旧 `ExpressionPlan` 字段。新链路稳定前保留兼容适配和回滚开关；稳定后另行清理旧抽象字段，避免在同一次改造中扩大不可逆范围。

## 20. 主要风险与控制

- **场景枚举膨胀：** 使用少量稳定场景族加结构化属性，不为每句群聊增加一个类型。
- **规则过硬：** 规则负责权限、证据和边界；语义识别与措辞仍允许模型发挥。
- **关系差别变成随机偏见：** 每次差异必须能追溯到关系维度、近期事件或可靠记忆。
- **检查器误伤自然语言：** 以句子功能和决策一致性为主，短语匹配只作信号。
- **双模型增加延迟：** 优先复用已有认知结果；只有成品不合格时进行一次修复，不增加无条件点评模型。
- **迁移影响已有路由：** Ownership 仍最先运行；`ChorusDetector` 只在未被命令认领后为 Participation 与 Governor 补充事实，不改变它们的暂停、隐私、边界、限流和平台硬门；通过兼容适配、SHADOW 对比和回滚开关控制切换。
- **原文复读绕过改写：** 只允许冻结的纯文本、安全 `JOIN_CHORUS` 使用逐字通道；其余安全、权限、幂等、冷却和平台检查全部保留。
- **误判复读靶心：** 复读链由确定性检测，靶心成员必须落在当前群目录；未知时沉默，不用好感或画像补猜。
