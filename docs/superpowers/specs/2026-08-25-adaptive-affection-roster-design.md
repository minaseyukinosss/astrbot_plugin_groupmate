# 自适应好感度群成员榜设计

日期：2026-08-25  
状态：已确认  
范围：`查看好感度` / `查询好感度` 的成员数据源、图片布局与降级路径

## 1. 问题与目标

现实现从 `participant_directory` 查询最近 30 天被 Groupmate 观察到的成员。该目录由消息发送者和部分被提及成员逐步写入，因此刚安装插件或沉默成员较多时，真实三人群也可能只展示查询者一人。

当前图片还将同一种多列表格用于所有规模，并依赖超过 AstrBot 实际截图视口的裁切宽度。小群因此空洞、重复且可能丢失右侧内容；大群则容易把文字压得过小。

本次目标：

1. 榜单成员以 NapCat 当前完整群成员为准，而不是以“发过言的人”为准。
2. 分别显示成员总数与近 30 天有互动人数，避免概念混淆。
3. 根据 1–10、11–50、51–100、100+ 四种规模选择清晰布局。
4. 图片内容必须完整落在 760 × 560 CSS px 的安全画布内，不依赖超过 AstrBot 默认截图视口的裁切。
5. 查询命令仍不调用模型，也不进入普通闲聊回复链路。

本规格取代原好感度系统设计中“仅近 30 天活跃成员入榜”和“约 240 人才拆图”的条款，其余关系分、隐私和表达规则保持不变。

## 2. 成员数据源

### 2.1 主数据源

查询处理改为异步。收到精确查询指令后调用当前 `AstrMessageEvent.get_group()`。在 AstrBot 的 aiocqhttp 适配器中，该方法通过 OneBot `get_group_info` 和 `get_group_member_list` 获取群资料与完整成员列表；NapCat 支持该接口。

每个成员规范化为：

- `actor_id`：平台成员 ID，仅用于当前群内关联与排序；
- `display_name`：优先群名片，其次昵称，最后使用“群成员”；
- `updated_at`：本次群名单同步时间；
- `interacted_recently`：本地参与者目录中最近 30 天是否出现。

机器人自身 ID 必须排除。查询者必须存在于结果中；平台返回异常时允许由当前事件补入查询者。

### 2.2 与关系投影合并

完整成员名单逐项交给现有 `AffectionLeaderboardService`。已有关系投影继续返回真实分数和阶段；从未互动过的成员使用关系系统定义的初始值 `0.0 / 陌生`，不会因没有历史而消失。

成员总数为平台名单去重并排除 Bot 后的数量。近 30 天互动人数由同步前的本地参与者目录计算，不得因为本次完整名单同步而将所有成员误记为近期活跃。

### 2.3 降级

`event.get_group()` 不可用、超时、返回空成员或结构无效时：

1. 使用本地最近 30 天观察名单；
2. 保证查询者在榜；
3. 图片标记“成员名单暂未完全同步”；
4. 不调用模型，不让命令静默失败；
5. 不在公开图片中显示原始平台错误。

## 3. 自适应图片布局

所有图片使用统一粉色系令牌和无损 PNG。渲染安全边界固定为最大 760 × 560 CSS px，为 AstrBot 实际约 800 × 600 的截图视口分别保留至少 40 px 安全余量。模板不得通过横向滚动、超视口 `clip` 或缩放挤压来容纳内容。标题区只保留：心形标识、`好感度`、群名、成员总数、近 30 天互动人数和更新时间。查询者在真实排名位置高亮，避免小群重复展示一条“我的位置”和一条相同成员记录。

所有布局还必须满足：

- `html`、`body` 与内容根节点使用同一明确尺寸；
- 最右侧分数、阶段和更新时间的边界不得超过画布右边缘；
- 最后一行和页码不得超过画布下边缘；
- 群名、昵称和辅助文本必须截断或换行，不能扩大画布；
- 截图参数只能裁切画布以内的区域，不能要求渲染器捕获视口之外的内容。

### 3.1 1–10 人：单列成员榜

- 宽度 720 px，高度不超过 540 px；
- 每行约 42 px，展示排名、昵称与 QQ 尾号、分数、关系阶段；
- 当前用户整行使用浅粉底、玫红描边和 `你` 标签；
- 前三名只增强排名数字，不添加奖杯或图标；
- 不显示独立置顶摘要，也不显示空表格。

该布局服务于当前常见三人或十人小群，优先保证昵称和分数一眼可读。

### 3.2 11–50 人：双列榜

- 宽度 760 px，高度不超过 560 px；
- 两列均分，每列最多 25 行；
- 每行约 19 px，表头随列重复；
- 保留昵称截断、QQ 尾号、分数和阶段；
- 单张图片完成，不分页。

### 3.3 51–100 人：四列榜

- 宽度 760 px，高度不超过 560 px；
- 四列均分，每列最多 25 行；
- 每行约 18 px；
- 减少装饰和留白，仍保持至少 10 px 的正文尺寸；
- 单张图片完成。

### 3.4 100 人以上：每页最多 100 人

- 每页使用四列，每列最多 25 行，画布不超过 760 × 560 px；
- 总榜按每 100 人拆页；
- 含查询者的页面优先发送；
- 每张图显示 `第 N / M 页`；
- 页面之间保持连续真实排名，不重复成员。

## 4. 组件与边界

### 4.1 `AstrBotSocialRuntimeBridge`

负责：

- 识别查询命令；
- 异步获取完整群成员；
- 调用参与者目录读取近期互动集合；
- 构造含完整成员、互动人数和同步状态的排行榜。

不负责 HTML 排版。

### 4.2 `ParticipantDirectory`

新增只读近期成员 ID 查询或等价接口。完整群名单的昵称可同步进目录，但此次同步不得更新“最近互动时间”，否则会污染活跃人数。

### 4.3 `AffectionLeaderboardService`

继续负责去重、关系快照合并、排序和查询者定位。增加独立的 `member_count`、`recent_active_count` 与 `roster_complete` 公共字段。

### 4.4 `AffectionCardPresenter`

根据排行榜总成员数决定布局层级、页大小、列数和尺寸。模板可通过布局类切换单列成员榜与多列表格，但共享颜色、排版和高亮规则。

## 5. 数据流

`查询消息 -> Groupmate 精确认领 -> event.get_group() -> NapCat 完整成员 -> 与本地近期互动集合合并 -> 关系投影排序 -> 自适应分页 -> HTML 渲染 PNG -> AstrBot 发送`

平台名单失败时：

`查询消息 -> Groupmate 精确认领 -> get_group 失败 -> 本地观察名单 -> 降级标记 -> 自适应渲染 -> AstrBot 发送`

无论成功或降级，事件都保持单一所有者，不触发 AstrBot 默认模型回复。

## 6. 测试与验收

仅运行定向测试：

1. aiocqhttp 群成员对象能够转为完整名单并排除 Bot；
2. 三人群中只有一人发过言时仍展示三人，互动人数为一；
3. 未互动成员为 `0.0 / 陌生`；
4. 平台成员查询失败时使用本地名单并标记降级；
5. 10 人为单列，50 人为双列，100 人为四列；
6. 101 和 228 人正确拆页，查询者页面优先；
7. 每张图不超过 760 × 560 px，且模板根节点的 `scrollWidth` / `scrollHeight` 不超过声明画布；
8. 当前用户只在真实排名行高亮，不重复占用置顶区；
9. 查询不调用模型、不进入普通聊天、不产生双回复；
10. HTML 生成失败仍返回包含本人排名、分数、阶段、成员总数和同步状态的文本兜底；
11. 使用最长群名、最长昵称、负分、最长阶段文本和最后一页进行边界测试；所有可见节点的边界框必须位于声明画布内；
12. 实际 AstrBot `html_render` 输出尺寸必须与声明画布一致，不接受浏览器预览正常但群内成图残缺。

验收以真实 NapCat 三人群截图为第一检查点：图片必须完整显示三名成员，右侧的更新时间、分数和阶段不得裁切，最后一行不得缺失，昵称、分数和阶段在 QQ 客户端预览中清楚可读。若实际群内图片与本地预览尺寸不一致，该版本不得打包交付。
