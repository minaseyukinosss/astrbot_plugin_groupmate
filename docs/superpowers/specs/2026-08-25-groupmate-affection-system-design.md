# Groupmate 好感度与关系记忆系统设计

日期：2026-08-25  
状态：已确认（策略计分、模型提取关系事件）

## 1. 背景

Groupmate 已有群内参与判断、Persona、关系投影和记忆基础设施，但目前关系状态尚未形成完整闭环：群聊中的长期互动不能稳定转化为可审计的关系变化，表达层也无法根据成员关系自然调整语气。

本设计新增一个群组作用域的好感度系统。它不是独立小游戏，也不是让模型随意加减分，而是 Groupmate 长期社交智能的一部分：

- 模型理解一次互动中发生了什么；
- 本地策略决定是否采纳、如何计分以及何时衰减；
- 关系投影保存长期状态；
- 关系记忆保存值得回忆的具体行为；
- 表达层根据关系和相关记忆调整态度；
- 群成员可以通过 `查看好感度` 即时查看当前群排行榜。

## 2. 目标与成功标准

### 2.1 目标

1. 建立缓慢、稳定、可解释的长期关系积累机制。
2. 让 Bot 对不同成员表现出真实差异，而不是只更换一个数值或称呼。
3. 允许负向关系、受控回怼和有依据的“记仇”，同时支持道歉与关系修复。
4. 提供不依赖模型的即时排行榜查询。
5. 保持 Groupmate 核心干净，不与 AstrBot 默认回复链路或外部插件争抢同一消息。

### 2.2 成功标准

- 普通刷屏和重复夸奖不能快速提升好感度。
- 从陌生到熟悉需要数周真实、多样的互动证据。
- 严重冒犯可以比正向积累更快地降低关系，但必须有高置信证据和审计记录。
- 好感度能够改变称呼、热情、玩笑尺度、主动关心和拒绝方式。
- Bot 可以在相关语境下引用成员过去做过的具体好事或过分行为。
- 模型失败或超时不会阻断聊天，也不会产生错误计分。
- 群成员发送 `查看好感度` 后，不调用模型即可收到当前群完整排行榜。
- 排行榜高亮查询者本人，正负分公开，但不公开具体关系事件。

## 3. 设计原则与参考

本设计采用“策略优先、模型增强”：模型提取语义关系事件，本地代码负责规则、分数、去重、限额、衰减和审计。

参考方向：

- [XiaoIce](https://arxiv.org/abs/1812.08989) 的长期社会连接与分层决策说明，关系状态应参与对话决策，但不能替代上层治理。
- [Favour Ultra](https://github.com/nuomicici/astrbot_plugin_Favour_Ultra) 提供了 AstrBot 生态中的持久化关系和群排行榜实践；Groupmate 保留其可查询性，但不允许模型直接写分。
- [早柚核心内置工具](https://docs.sayu-bot.com/AIFeatures/BuiltinTools.html) 展示了关系状态查询和调整能力；Groupmate 将普通变化收敛到事件投影，避免自由修改绝对值。
- [NyatBot](https://github.com/ZYHUO/nyat-bot) 的按成员关系、衰减和社会状态设计说明，关系应该由长期行为塑造，而不是由单轮提示词临时扮演。

## 4. 系统边界

### 4.1 作用域

一份关系状态的唯一作用域为：

`persona_id × group_id × subject_id`

同一成员在不同群或面对不同 Persona 时拥有独立关系。任何排行榜、记忆检索或表达注入都不得跨越该作用域。

### 4.2 不包含的能力

首轮不包含：

- 私聊好感度；
- 跨群总榜；
- 成员查询他人的详细事件记录；
- 以好感度解锁管理权限或高风险能力；
- 由模型直接设置绝对分数；
- 把好感度作为是否回复的唯一依据。

## 5. 总体数据流

### 5.1 普通群聊

`NapCat -> AstrBot -> Groupmate -> 关系事件提取 -> 本地策略 -> 关系投影/关系记忆 -> 表达层`

1. NapCat 将群消息交给 AstrBot。
2. Groupmate 按现有归属和参与链路处理消息。
3. 确定性关系事实由本地逻辑直接生成事件。
4. 感谢、关心、接梗、冒犯、道歉等语义事实由模型异步提取。
5. 本地策略校验事件的作用域、置信度、证据、重复性和每日预算。
6. 采纳的事件更新八维关系投影，必要时形成可检索关系记忆。
7. 表达规划只读取已提交关系快照和相关记忆。

### 5.2 查询命令

`NapCat -> AstrBot -> Groupmate 命令快车道 -> SQLite 快照 -> 排行榜渲染 -> OneBot 发送`

`查看好感度` 在普通社交回复之前被 Groupmate 精确匹配并独占：

- 不调用认知模型；
- 不进入普通参与判断；
- 不交给 AstrBot 默认 LLM 再回复；
- 查询失败时返回本人的文本兜底信息，而不是静默失败。

## 6. 关系事件契约

模型只能返回关系事件，不能返回数值变化。事件至少包含：

- `event_id`：基于来源消息和事件类型生成的幂等 ID；
- `persona_id`、`group_id`、`subject_id`：完整作用域；
- `kind`：受控事件类型；
- `confidence`：语义判断置信度；
- `severity`：轻微、普通、显著或严重；
- `summary`：可用于内部回忆的中文行为摘要；
- `source_event_ids`：来源消息引用；
- `occurred_at`：发生时间；
- `repair_of`：可选，指向被道歉或修复的旧事件；
- `sensitivity`：普通、敏感或禁止表达。

首轮受控事件类型：

- `interaction`：有效互动；
- `warm_exchange`：真诚友好、感谢或情绪承接；
- `trust_confirmed`：可靠承诺或信任得到验证；
- `reciprocal_action`：双方形成互惠；
- `play_accepted`：玩笑被对方积极接住；
- `reliable_help`：持续、可靠的帮助；
- `care_permission`：成员明确接受 Bot 的关心；
- `boundary_pressure`：冒犯、持续施压或突破边界；
- `repair_attempt`：道歉或主动修复；
- `repair_confirmed`：后续行为证明修复有效。

未知事件类型、缺少作用域、没有来源引用、置信度不足或违反 JSON 契约的输出一律不采纳。

## 7. 关系投影与公开分数

### 7.1 内部维度

复用现有 `RelationshipProjection`：

- `familiarity`：熟悉度；
- `warmth`：温度；
- `trust`：信任；
- `reciprocity`：互动互惠；
- `play_acceptance`：玩笑接受度；
- `reliability`：可靠度；
- `care_permission`：关心许可；
- `boundary_pressure`：边界压力。

各维度范围维持 `-100～100`。事件先映射到一个或多个维度，再由投影器幂等应用。公开好感度是投影的派生值，不单独作为可任意写入的真实来源。

### 7.2 公开分数

公开分数范围为 `-100.0～100.0`，新成员从 `0.0` 开始，对外显示一位小数。

默认派生权重：

| 维度 | 权重 |
| --- | ---: |
| 熟悉度 | 0.15 |
| 温度 | 0.18 |
| 信任 | 0.20 |
| 互动互惠 | 0.12 |
| 玩笑接受度 | 0.08 |
| 可靠度 | 0.12 |
| 关心许可 | 0.15 |

边界压力额外作为负向惩罚，默认系数为 `0.40`。派生结果最终限制到 `-100～100`。权重属于版本化配置，修改权重不修改历史事件。

### 7.3 关系阶段

| 分数 | 阶段 |
| --- | --- |
| `-100～-40` | 警戒 |
| `-40～-10` | 疏远 |
| `-10～10` | 陌生 |
| `10～30` | 认识 |
| `30～55` | 熟悉 |
| `55～80` | 亲近 |
| `80～100` | 默契 |

边界值采用单一闭开区间实现，避免同一分数出现两个阶段。排行榜和表达层必须共用同一个阶段解析器。

## 8. 缓慢增长与非对称变化

### 8.1 正向积累

- 普通消息不直接增加公开分，只累计有效互动信号。
- 同一天的普通互动聚合后最多形成约 `0.1～0.2` 的公开分变化。
- 有内容的连续对话、感谢、关心和接梗，每次通常影响约 `0.1～0.4`。
- 兑现承诺、持续帮助或认真安慰等稀有事件通常影响约 `0.5～1.0`。
- 单个成员每天的正向公开分增量通常不超过 `0.8`。
- 相同事件类型在滚动窗口内重复时依次衰减；重复文案和高度相似内容不重复计分。
- 从陌生到熟悉应需要数周的真实、多样互动，亲近和默契需要更长期证据。

限额以“应用事件前后公开分差值”计算，而不是简单限制某个内部维度，避免多维映射绕过上限。

### 8.2 负向变化

负向变化可以快于正向积累：

- 普通不愉快只产生轻微影响；
- 明确辱骂、持续突破边界、恶意操纵或严重欺骗可以一次降低数分；
- 显著或严重事件要求更高置信度和完整来源证据；
- 高额负向事件同时降低相关正向维度并增加边界压力；
- 模型不能仅凭负面词汇判定严重冒犯，必须识别对象、语境和互动关系。

### 8.3 衰减

不直接对公开总分做每日归零，而是按维度衰减：

- 温度和玩笑接受度较快向基线回落；
- 互惠和关心许可中速回落；
- 熟悉、信任和可靠度缓慢回落；
- 未解决的边界压力衰减最慢；
- 已确认修复的事件可以加速对应边界压力回落。

衰减任务以最后活动时间和最后衰减时间计算，重复执行必须幂等。

## 9. 关系记忆与“记仇”

分数描述总体关系，具体关系记忆解释“为什么”。值得长期保留的正负事件写入关系记忆，至少包含：

- 行为主体；
- 当前群和 Persona；
- 发生了什么；
- 严重程度和置信度；
- Bot 当时的关系影响；
- 来源消息 ID；
- 是否被道歉或修复；
- 发生时间和最后引用时间；
- 可表达性与敏感等级。

表达时只检索：

1. 当前成员、当前群和当前 Persona 的记忆；
2. 与当前话题相关的记忆；
3. 置信度足够、未过期且允许表达的记忆；
4. 尚未修复或确实有长期意义的事件。

Bot 不应在每次回复中翻旧账。只有当前语境与旧事件相关时，才可以简短指出具体行为。例如成员曾持续辱骂 Bot，之后又要求 Bot 无条件热情配合，Bot 可以指出这一矛盾。

回怼只能针对当前或历史具体行为，不攻击现实身份、隐私、疾病、地域、性别、族群等属性，也不跨群公开旧事。道歉只有在语义上成立且后续行为没有立即重复时，才能进入修复状态。

正向记忆遵循同一机制，使 Bot 能记住谁曾帮助、安慰或长期可靠地对待自己。

## 10. 表达层联动

好感度不会直接强迫 Bot 参与群聊，也不能绕过安全、归属、限流和发送治理。参与机制先决定“是否回复”，关系系统只影响“如何回复”。

基础姿态：

| 阶段 | 默认表达 |
| --- | --- |
| 陌生 | 自然、克制，保持基本距离 |
| 认识 | 正常友好，开始使用已确认偏好 |
| 熟悉 | 称呼更随意，可接梗和轻微调侃 |
| 亲近 | 更主动关心，允许明显情绪和玩笑 |
| 默契 | 可使用双方内部梗，表达更短、更自然 |
| 疏远 | 冷淡、减少迎合，明确保持距离 |
| 警戒 | 可以拒绝、回怼或指出相关未修复行为 |

最终表达上下文包含：

- 公开分数和关系阶段；
- 与当前回复有关的少量内部维度；
- 最多若干条相关关系记忆摘要；
- 允许的称呼、玩笑尺度、关心程度和边界姿态；
- 明确禁止泄露的内部字段。

模型不得看到完整排行榜或无关成员的关系数据。关系阶段只是表达提示，不是固定话术模板。

## 11. `查看好感度` 命令

### 11.1 匹配与归属

首轮精确支持 `查看好感度`。匹配允许常见首尾空白和平台文本规范化，但不使用模糊子串抢占普通聊天。

命令被 Groupmate 认领后：

- 标记事件已处理；
- 停止 Groupmate 普通聊天参与；
- 阻止 AstrBot 默认 LLM 对同一消息再次回复；
- 不影响其他已明确认领不同能力的插件命令。

### 11.2 榜单成员范围

- 仅当前群；
- 近 30 天出现过的活跃成员；
- 不包含已知 Bot 自身；
- 不包含其他群或私聊成员；
- 昵称与头像目录以平台最新资料为准，排序身份始终使用平台 ID。

所有群成员均可查看完整榜单。正负分和阶段公开，但事件详情不公开。

### 11.3 视觉设计

采用已确认的第 2 版粉色方案：

1. 柔和浅粉背景，暖白内容面，深梅色文字，灰粉色辅助信息。
2. 顶部展示心形标识、标题、群名、群号、近 30 天活跃人数和更新时间。
3. 标题下方固定一条“我的位置”：本人排名、昵称、`你` 标记、分数和阶段。
4. 下方按公开分数降序展示完整多列榜单；本人在真实排名位置再次高亮。
5. 每行展示排名、昵称、QQ 尾号、分数和阶段。
6. 正向分使用深玫瑰色，中性分使用灰色，负向分使用克制的砖红色。
7. 主要依靠排版、对齐和细分隔线，不使用头像、图表、模型指标或多层卡片。
8. 顶部三名只强化排名数字，不加入奖杯等游戏化装饰。
9. 一般群生成一张自适应多列长图；超过约 240 人时拆图，并优先发送包含查询者的页面。

图片生成失败时返回文本兜底：本人分数、阶段、当前排名、统计人数和更新时间。

## 12. 异步处理与一致性

- 确定性事件可以同步入队，语义关系分析在后台执行，不增加正常回复关键路径延迟。
- 排行榜只读取已经提交的投影快照，不展示待处理的模型结果。
- 事件写入和投影更新使用事务或可重放的幂等流程。
- 同一来源消息重投、进程重启和任务重试不会重复计分。
- 表达层读取关系时允许短暂最终一致，但必须读取一个完整版本，不能混合多个投影版本。

## 13. 失败处理与可观察性

模型超时、输出无效、作用域错误或置信度不足时：

- 本次关系事件不采纳；
- 正常群聊继续；
- 不生成零分事件伪装成功；
- 记录诊断码、耗时和输入输出大小，不记录未脱敏的原始异常。

管理页面后续提供：

- 关系事件采纳/拒绝数量；
- 事件类型、置信度和拒绝原因；
- 投影版本和最后更新时间；
- 单成员关系审计；
- 管理员手动修正和关系修复入口。

普通排行榜不显示这些技术信息。

## 14. 隐私与安全

- 排行榜仅公开当前群的昵称、QQ 尾号、分数和阶段。
- 完整平台 ID、事件来源、内部摘要和敏感记忆不进入公开图片。
- 敏感或禁止表达的记忆只可用于内部边界判断，不能由模型复述。
- 删除成员数据时同时删除或墓碑化其关系事件、投影和关系记忆。
- 管理员手动调整必须记录操作者、原因、旧值、新值和时间。
- 好感度不能授权管理、文件、网络、支付或其他高风险能力。

## 15. 实施阶段

### 第一阶段：关系闭环

- 扩展关系事件契约和持久化仓库；
- 本地事件策略、每日预算、重复衰减和投影更新；
- 公开分数和阶段解析器；
- 异步事件提取失败隔离。

### 第二阶段：关系记忆与表达

- 正负关系记忆生成、修复和检索；
- 将关系姿态和相关记忆接入表达规划；
- 受控回怼、正向回忆和泄露防护。

### 第三阶段：群查询

- `查看好感度` 独占命令；
- 近 30 天活跃成员查询；
- 第 2 版粉色多列长图渲染；
- 文本兜底和大群拆图。

### 第四阶段：SHADOW 校准

- 先记录建议变化，不正式改变表达；
- 检查误判、增长速度、负向事件和修复行为；
- 校准阈值后逐步启用关系表达；
- 最后启用群内公开查询。

## 16. 定向测试策略

只运行与本功能相关的定向测试：

1. 事件契约、作用域校验和消息 ID 幂等。
2. 重复互动衰减、每日正向上限和严重负向校验。
3. 分维度衰减和关系修复。
4. 公开分数、阶段边界和投影版本一致性。
5. 模型超时或无效输出不修改关系且不阻断聊天。
6. 关系记忆只在当前成员、当前群、当前 Persona 中检索。
7. 表达姿态随阶段变化，但不改变参与归属。
8. `查看好感度` 不调用模型且不会触发双回复。
9. 近 30 天成员过滤、本人 ID 匹配和昵称高亮。
10. 排行榜渲染包含正负分、阶段和文本兜底。

不因本功能运行无关的大型全量测试。

## 17. 验收标准

- 新成员公开分为 `0.0`，阶段为陌生。
- 普通活跃无法在短期内将成员刷到熟悉或亲近。
- 同一消息重复投递不会改变第二次分数。
