# 回执约束的双向对话与回复锚点

用户已在对话中确认设计并授权实施；在当前工作区执行，不提交 git。

## 目标与边界

修复参与模型缺少双方前情、场景回退不可见、选中对象与下游源消息不一致。复用 Inbox、Outbox、捕获证据 JSON，不建表、不新增模型调用，不修改 AMBIENT 阈值、TTL、租约时长/轮数、SHADOW 发送门、冷启动、媒体或 DeepSeek 接入方式。工作区原有改动保留。

## 设计

1. 场景解释保留既有 diagnostic_code，并新增有界诊断：请求/解析/字段/引用失败、字段类型及安全错误代码。不保存请求头或未经脱敏的原始返回。成功继续生成的回退也写入独立 scene_diagnostic，不能把 delivery 误标为失败。补齐已存在的 JSON 字段契约；不枚举 scene_kind，不自动重试或猜补目标。
2. 在冻结 world.recent_presence 的 50 个事件范围内构建只读对话。只对其中 delivery.sent 通过 part_id 读取相同 persona/group 的 SENT Outbox 正文与回执，生成只用于上下文的 BOT_TEXT 事实，不 append 新事件。保留事件身份、原文、时间、回复关系、真实 bot_id；与平台回显按平台消息 ID 去重。未发送、未知、外部命令、其他群不能进入事实。这个范围以外的久远对话不是本轮解决对象。
3. 从冻结候选记录中优先选择当前窗口、显式回复链、与候选成员有关的 bot 往返，再补附近群聊；复用现有 16 条 / 2400 字符预算，最终按时序排列。同一组事实传入认知、场景、普通及知识生成并写入既有 capture JSON。不将历史加入 focus_event_ids。
4. CognitiveContext 增加默认空的 context_events。参与模型可输出默认空 context_evidence_event_ids；仅可引用实际提供的历史。原 evidence_event_ids 仍限 focus，anchor 必须是当前合格消息，Blackboard、Governor、关系事件证据边界不放宽。
5. CandidateIntention 增加默认空 anchor_event_id，通过既有 JSON 自动恢复兼容。语义候选使用已验证 anchor，确定性路径保持原有授权。ShadowEvaluation 提供 resolve_reply_source()：仅根据已选候选锚点/旧候选匹配证据解析；桥接器的场景、画像和生成使用该源消息，原 source_event 保留用于 trace/请求身份。ReplyPlanner 使用锚点时间计算原有年龄上限，而非最后一条背景消息的时间。

## 失败与验证

实现核对补充：近期上下文按目标报告已有的 300 秒静默间隔断开，明确引用的父消息不受背景分段限制；同秒消息按冻结事件顺序排列。已选择锚点也驱动本地知识解析，但 correlation_id 保留原决策身份以确保回执结案。安全序列化保存机会类型、锚点和受限历史证据 ID，Blackboard 的行动证据集合不变。

审查收尾：SceneContextBuilder 在运行链路复用已预算的冻结事实，不二次裁剪；回复源优先使用规范化后的冻结副本。Chorus 检测继续仅取原有最近 20 条，已检测的必要链证据优先保留为上下文，不扩展可行动消息。

缺失旧字段默认空；旧的无正文回执通过 Outbox 读取兼容。历史缺失时使用当前窗口，不伪造历史。场景具体生产根因需要真实 provider 返回验证；本地固定返回只能验证契约与诊断，不是线上效果证明。

用少量真实组件测试覆盖回执读取隔离/去重、历史只作证据、场景失败保留和多人窗口锚点贯通。全量运行用户指定三组测试及涉及的 contracts。对生产库只读重建两个三角洲事件的输入，不调用外部模型、不发送；没有真实模型对照就不宣称召回率或风格改善。
