# 目标群聊 Bot 行为分析与 Groupmate 下一阶段设计

## 执行摘要

这份导出显示，目标 Bot 的“像群友”主要不是来自随机主动发言，而是来自四件事：**及时接住直接互动、维持短程连续对话、少量且受控地加入环境话题、用图片和短句形成群聊节奏**。

- 1,647 个 Bot 发言轮次中，48.4% 是连续对话，27.1% 来自被点名或被回复；真正脱离上下文的主动开场只有 0.12%。
- 回复速度是体验的一部分：发言轮次的近似响应时延中位数为 4 秒，P90 为 15 秒；单轮文本长度中位数为 14 字，P90 为 53 字。
- 72.1% 的发言轮次含图片或其他媒体，32.1% 会拆成多条消息；但启发式识别出的工具/插件式轮次只占 4.9%。媒体很重要，但不等于插件功能就是核心。
- 当前 Groupmate SHADOW 数据仍未形成可评估的智能决策闭环：780 条已完成跟踪全部是 OBSERVE，408 条治理结果全部为 `forced_observe`，认知观察与候选意图表均为空；已完成链路耗时中位数约 23 秒、P90 约 36 秒。

因此，下一阶段不应先继续扩充外围插件，而应先做出一条可工作的群聊主链：**直接响应快车道 → 对话续租 → 受控环境介入 → 输出形态规划 → 反馈记录**。

## 数据范围与可信度

目标群聊导出包含 16,914 条记录。去除系统消息并按消息 ID 去重后，分析 16,622 条活跃消息，其中目标 Bot 2,333 条、群成员 14,289 条。目标 Bot 通过账号标识识别，不依赖昵称，因此不会与群内同名成员混淆。

Excel 版对相同时间窗口进行了交叉校验：目标 Bot 原始消息数均为 2,338，回复类消息均为 540，视频均为 173，转发均为 41，说明 JSONL 的账号识别和主要消息元素解析可靠。两种格式在窗口内的总行数相差 2 条，另有 JSONL 中 5 个重复消息 ID，但这些差异不影响 Bot 行为结论。

Excel 的 `发送者统计` 页存在一个明确的数据质量问题：它按显示昵称合并同名成员，导致目标 Bot 的 2,541 条全时段消息与另一同名成员的 52 条消息合并成 2,593 条。因此本文不采用该汇总页的 Bot 排名和占比，只使用 `聊天记录` 页中的 QQ 号以及 JSONL 中的 UIN/UID 做身份判定。

数据适合分析互动机制，但不适合推断长期在线率：导出跨越 33 个自然日，却只有 6 天存在非系统消息，前三个日期承载 97.7% 的有效记录。另有 97.4% 的回复元素缺失可解析的原消息 ID，因此本文的响应时延是相对“Bot 发言前最近一条群成员消息”的近似值，不能视为精确的端到端请求时延。

主要分类阈值为：5 分钟切分会话、90 秒内连续 Bot 消息合并为一个轮次、120 秒内无直接召唤的跟进视为环境介入。使用 30–120 秒轮次窗口和 60–180 秒环境窗口进行敏感性检查后，核心分类比例变化不足 1.3 个百分点，主要结论稳定。

## 目标 Bot 的参与机制

| 进入方式 | 轮次 | 占比 | 近似时延 P50 / P90 | 2 分钟内明确回访 |
| --- | ---: | ---: | ---: | ---: |
| 连续对话 | 797 | 48.4% | 3 / 10 秒 | 18.3% |
| 被点名/被回复 | 447 | 27.1% | 5 / 17 秒 | 38.9% |
| 自主定向回复 | 204 | 12.4% | 5.5 / 18.7 秒 | 27.9% |
| 环境话题加入 | 189 | 11.5% | 4 / 14 秒 | 11.1% |
| 延迟上下文 | 8 | 0.5% | 151.5 / 256.4 秒 | 25.0% |
| 主动开场 | 2 | 0.1% | 无 | 0% |

这里最重要的不是复制比例，而是复制控制结构：

1. **直接互动优先。** 被点名/被回复的明确回访率最高，说明这是最可靠的参与信号，应走低延迟路径。
2. **对话需要“续租”，而不是每条消息重新决定。** 数据中有 344 条多轮对话链，中位数包含 3 个 Bot 轮次，P90 约 6 个轮次。若每次都从零计算“要不要说话”，连续感会被破坏。
3. **主动性主要表现为定向接话和环境加入。** 两者合计 23.9%，而真正的冷启动开场近乎不存在。所谓智能主动，不是随机抢话。
4. **环境加入必须更谨慎。** 它的明确回访率只有直接互动的约三分之一，应该有更高的相关度、风险和频率门槛。

## 像群友的输出形态

目标 Bot 的发言轮次平均包含 1.42 条消息，32.1% 会拆成两条或更多；单轮文本中位数仅 14 字。它更接近“短反应 + 补一句/发图”，而不是一次生成完整小作文。

媒体不是边缘现象：72.1% 的轮次含媒体，32.0% 是纯媒体轮次，40.1% 是文本与媒体混合轮次。按消息元素统计，56.8% 的 Bot 消息含图片，7.4% 含视频，23.1% 使用回复引用。

这对 Groupmate 的含义是：

- 核心只决定**是否参与、回应谁、表达意图、允许几条消息以及是否需要媒体能力**。
- 表情包、视频解析、群管理等能力由适配器执行，不应反向污染注意力与参与决策。
- 媒体选择应进入“表达规划”，而不是只有命令式插件才会产生媒体。聊天核心可以提出 `REACTION_IMAGE` 或 `MEME_SEARCH` 需求，但由能力层决定是否可用和如何生成。
- 输出规划应支持 1–2 条短消息，默认避免把所有内容压成一段长文本。

## Groupmate 当前链路的主要问题

对同日提供的 SHADOW 数据库重新核验后：

- 1,544 条消息跟踪中，780 条完成理解和决策，764 条仍处于 PENDING。
- 780 条完成决策全部为 OBSERVE；408 条治理结果全部是 `forced_observe`。
- `attention_frames`、`cognitive_observations`、`candidate_intentions`、`action_plans` 和 `reply_plans` 均无可评估记录。
- 已完成链路耗时中位数约 23 秒，P90 约 36 秒，只有 0.3% 在 15 秒内完成。

这意味着当前数据展示虽然能够说明“消息走到了哪里”，但还不能回答“如果允许发送，Groupmate 本来想不想说、为什么、准备说什么”。在这种状态下继续跑更久的 SHADOW，新增数据的边际价值很低。

## 建议的干净主链

```text
NapCat 原始事件
  → AstrBot 前置路由（命令 / 外部插件可截获）
  → Groupmate CanonicalEvent（文本、@、回复、图片、视频统一表达）
  → GroupScene 更新（话题、参与者、最近轮次、Bot 对话租约）
  → ParticipationPolicy
      1. DIRECT_FAST：被 @、被回复、明确叫名
      2. CONTINUATION：已有对话租约内的接续
      3. AMBIENT：高相关、低风险、受频控的环境介入
      4. PROACTIVE：默认关闭或极低频的冷启动
  → ResponsePlan（对象、意图、长度、消息数、表达形态、能力需求）
  → Capability Adapter（LLM、表情包、视频解析等）
  → DeliveryGate（模式、风控、去重、冷却）
  → AstrBot / NapCat 发送
  → OutcomeEvent（发送、明确回访、对话续租、人工标注）
```

主链中需要保持纯净的对象只有五类：`CanonicalEvent`、`GroupScene`、`ParticipationDecision`、`ResponsePlan`、`OutcomeEvent`。具体插件的数据结构不应进入这些核心模型，能力层只通过稳定的 capability contract 与核心交互。

## 下一阶段开发顺序

### P0：先让 SHADOW 产生真实候选决策

1. 修复认知降级，保证 `cognitive_observation` 和 `candidate_intention` 在正常消息上非空。
2. 将 SHADOW 的“禁止发送”放在 DeliveryGate，而不是让它提前把参与决策强制改成 OBSERVE。
3. 即使最终不发送，也持久化 `would_reply`、触发通道、目标成员、置信度、风险、响应计划摘要和放弃原因。
4. 先实现 `DIRECT_FAST` 与 `CONTINUATION` 两条路径，并把完整决策 P50 控制到 5 秒左右、P90 控制到 15 秒以内。目标值应在本群继续校准，而不是机械照搬目标 Bot。

### P1：实现真正的多轮连续感

1. 增加对话租约：明确交互后允许在约 3 分钟或 3–6 个 Bot 轮次内低成本续租。
2. 租约记录对话对象、当前话题、未完成问答、最近表达意图和退出条件。
3. 新消息到来时优先判断“是否延续现有互动”，再决定是否重新做全量环境参与判断。
4. 输出规划支持 1–2 条短消息，并对重复套话、连续刷屏、长回复设置约束。

### P2：加入受控环境参与与表达能力

1. `AMBIENT` 使用更高阈值，并加入冷却、近期发言占比、话题相关度和成员打断风险。
2. 冷启动 `PROACTIVE` 默认关闭；只有在有明确场景信号时开启，例如长时间沉默后的任务提醒或群内事件。
3. 将图片/表情包作为表达计划的一部分接入，但继续通过 AstrBot/Groupmate capability adapter 隔离实现。
4. 使用匿名化成员覆盖率检查偏置；目标 Bot 的定向回复覆盖 95 名成员，最高单一对象只占 9.4%，说明不能只围绕管理员或高频成员工作。

## 下一轮 SHADOW 应看的指标

下一轮不再只看“处理了多少消息”，而应至少展示：

- 认知可用率：非降级 `cognitive_observation / eligible messages`。
- 候选率：各通道产生候选意图的消息占比。
- 参与分布：DIRECT_FAST、CONTINUATION、AMBIENT、PROACTIVE 的候选与被治理拦截数量。
- 决策时延：从 RECEIVED 到 ParticipationDecision 的 P50/P90；生成和发送时延单独统计。
- 对话续租：链长度、续租次数、退出原因。
- 影子命中：人工复核的“应该回 / 不该回 / 回得太晚 / 对象错误 / 表达形态错误”。
- 表达结果：文本、纯媒体、混合媒体、拆分消息数量及明确回访率。

只有当候选意图不再全为空、人工复核有样本、直接与连续两条路径的时延进入可接受范围后，才值得逐步从 SHADOW 切到小流量真实发送。

## 结论

目标 Bot 最值得借鉴的不是某个插件，而是一套克制的参与策略：**先接住，再延续，偶尔加入，几乎不凭空开场；用短句和媒体完成群聊表达。**

Groupmate 当前的第一优先级不是增加更多功能，而是把“理解—候选—参与决策—表达计划”真实跑通，并让 SHADOW 记录“本来会怎么做”。在此基础上，表情包和视频等能力才会成为智能闲聊的表达工具，而不是把核心重新变成插件调度器。
