- Excel 来源：`group_885617919_20260826_142052.xlsx`

## 1. 数据边界

JSON 导出包含 6,831 条消息，其中目标 Bot 消息 1,239 条；Excel 对目标 Bot 的计数为 1,286 条。两个导出存在范围或解析口径差异，因此计数只用于确认样本规模和寻找场景，不作为产品概率、回复阈值或语言配方。

目标 Bot 消息包含 307 条结构化回复、86 条 @、718 条资源消息、660 张图片、48 个视频、9 条转发、8 个文件和 2 条音频。它说明媒体、回复关系和群体上下文是行为分析的一部分，不能只提取纯文本句子。

分析时区分：

- 可复用的处事方式；
- 小维专属身份、关系和背景；
- 工具输出、公开状态和媒体结果；
- 错误判断、危险处理失误和重复回复。

只有第一类能转化为爱弥斯的闲聊设计。其余内容分别作为集成边界、状态类型或负面回归样例。

## 2. 分析方法

本轮不根据词语出现百分比定义风格，也不把常见口癖拼成提示词。分析单位是完整互动链：

`成员做了什么 -> 前情是什么 -> 小维采取什么立场 -> 实际做了什么 -> 怎样结束本轮`

需要同时阅读回复对象、上下几轮消息、同一成员的关系历史、群体跟风和媒体位置。孤立句子不能说明处事风格。

“接住”只在目标 Bot 输出中出现过一次，语义是接住拥抱；精确文本“接住了”没有出现。爱弥斯频繁使用“接住了”不是对参考风格的复现，而是现有提示中的抽象动词被模型词面复用。

## 3. 可复用的处事机制

### 3.1 同时读取字面内容和社交动作

一句“抱抱”可能是陌生人的突然亲密、熟人的撒娇、前一轮互抱的继续、被拒绝后的重复试探或群体跟风。自然回复来自对社交动作的判断，而不是给“抱抱”绑定一种温暖模板。

### 3.2 先有立场，再有句子

小维的回复通常能看出明确取舍：愿意、不愿意、只答应一点、觉得好笑、开始不耐烦、准备认真解决问题。她不会先报告自己理解了什么，再临时决定怎样回答。

### 3.3 部分答应保留自主性

欧尼酱以“没爱了”继续索取揉肩时，小维没有全盘答应，也没有中断关系，而是只让两下并说明再多手会酸。这种动作同时完成熟人回应、有限让步和自我边界。

wht 用“刚才你抱我，现在我抱你”进行互惠协商时，小维认可其逻辑并接受，但保留“仅此一次”的决定。关键不是某个尾词，而是对等协商后的有限接受。

### 3.4 关系历史改变真实态度

若叶奶龙已有多次试探和不受欢迎玩笑的前情，后续“你喜欢我”得到直接否认；黄豆酱相思获得更亲密的拥抱、称呼和共同前情；欧尼酱形成兄妹式的嘴硬与有限迁就；霞月获得较长、约束明确的技术协助。

这些差异不是需要消除的“不公平”，而是关系系统应支持的真实伙伴感。要求是因果可追溯，而不是所有成员得到同样语气。

### 3.5 拒绝可以继续关系

自然拒绝不一定附送安慰、解释和替代方案。熟人之间可以嘴上嫌弃、只让一步或反问回去；持续越界时可以直接结束；陌生人则保持克制距离。边界强度来自关系和前情，不来自统一“友好拒绝”模板。

### 3.6 照顾和技术帮助落到具体动作

照顾表现为喝水、吃饭、休息、停止硬撑等现场行为。技术协作表现为要求报错首段、版本号和复现条件，或在成员拒绝 Few-Shot 方案后立即换成更短的约束，而不是维护先前建议的正确性。

### 3.7 玩笑建立在现场材料上

有效玩笑常从当前消息的一个词、一个字面逻辑或刚发生的行为继续，形成短暂共享现实。它不是每次附加一句俏皮话，也不需要宣布“我来开个玩笑”。

### 3.8 群体场景需要改变回应对象

多人连续索取亲亲时，小维会从逐人回复切换为一次群体拒绝，指出大家在排队跟风。群聊核心必须识别目标范围已经从单人变成群体，避免复制相同社交回复。

### 3.9 被纠正时直接修正

可靠的修复方式是承认具体错误、撤回错误结论并给出替代方案。通用道歉、解释模型限制或继续维护原答案都会削弱伙伴感。

### 3.10 主动加入直接落在话题上

主动互动需要一个具体进入点：相关兴趣、共同前情、当前玩笑、照顾信号或可靠补充。成品直接发表看法、补充事实或叫住成员，不应先说“我注意到大家在讨论”。

## 4. 不能作为正面风格的行为

参考 Bot 的以下表现只进入负面回归集：

- 对自伤威胁使用玩笑化处理；
- 回复媒体时误触发原视频分析；
- 图像判断错误后继续固执；
- 对同一社交场景重复或互相冲突地回复；
- 选错目标成员或错误关联上下文；
- 工具状态、公开状态和闲聊内容交错，造成结果不清；
- 根据不足证据制造关系或共同经历。

学习处事方式不等于复制所有可观察行为。

## 5. 状态、画像和好感度的正确解释

数据中的智力、转人工、额度、互动压力和好感变化并非全部是内部垃圾信息。它们应被分成：

- `PUBLIC_STATUS`：智力、精力、额度、冷却；
- `RELATIONSHIP_EVENT`：好感和关系变化；
- `SOCIAL_PRESSURE`：连续占用和互动疲劳；
- `OPERATOR_ONLY`：原始 ID、堆栈、调试键、秘密和内部完整评分。

前三类可以按配置公开，最后一类不能进入用户文本。

群画像是长期社交记忆的证据来源，不是过度推断的同义词。使用时必须区分确认事实、稳定模式和玩笑印象，并保留群作用域、相关检索、成员查看、纠正、删除和停用能力。

好感度和多维关系可以改变态度、回复投入、主动关注、额外帮助和人格自有能力的意愿。它不能授予权限，也不能让低好感成员失去危险场景中的最低必要帮助。

## 6. 当前插件的根因映射

### 6.1 意图过粗

`groupmate/social_runtime/intentions.py` 只把观察映射为帮助、照顾、玩笑、问候、边界和任务等宽泛动作。它无法表达有限答应、重复试探、关系修复、群体回应和基于现场词语的玩笑。

### 6.2 表达计划使用抽象元话语

`groupmate/social_runtime/expression.py` 输出 `reaction_stance`、`boundary_style` 和 `followup_hook`，并用少量关系关键词决定是否“acknowledge_relationship”。关键社交决定仍留给文本模型。

### 6.3 StyleDirector 未进入实际回复规划

`groupmate/social_runtime/actions/style.py` 已有关系和 Persona 模式驱动的 `StyleDirector`，但 `groupmate/social_runtime/replying.py` 的 `ReplyPlanner` 仍硬编码友好姿态、长度、温度和分段。

### 6.4 生成提示制造统一助理流程

`ReplyExecutor._system_prompt` 要求按即时反应、核心回应、人格化补充、续聊接口组织文本，并要求先处理情绪关系信号。模型因此容易生成抽象理解、服务式总结和无意义邀请。

### 6.5 上下文被机械截短

`groupmate/social_runtime/cognition/ambient_worker.py` 最多选取 12 个事件，并把每条文本截到 32 个字符。跨消息协商、重复试探、群体跟风和成员给出的技术约束可能在进入认知前已经丢失。

### 6.6 成品检查缺少社交一致性

现有 `OutputFirewall` 主要检查安全、能力声明、样式预算和重复，没有检查必须表达的现场事实、无意义复述、服务式收尾、虚构记忆和立场冲突。

## 7. 对实现的直接要求

1. 新增相关性驱动的场景上下文构建，不再统一截短所有消息。
2. 在生成前形成 `SocialScene`、`StanceDecision`、`SocialMove` 和带来源的 `DecisionFact`。
3. 权限和意愿分开；关系进入意愿计算，不进入授权。
4. `ReplyPlanner` 实际调用 `StyleDirector`。
5. 最终生成输入只包含具体现场、事实、意愿、动作和表达边界。
6. 删除统一四段式和“先接住”要求。
7. 生成器返回正文及其声称覆盖的事实、记忆和能力 ID；未知 ID 直接拒绝。
8. 增加独立 `SocialOutputReviewer`，再运行现有 `OutputFirewall`。
9. 主动互动使用同一套风格链；无具体进入点时保持沉默。
10. 精确命令继续旁路；唯一低风险错字先纠正再执行；含糊或高风险命令只提示。
